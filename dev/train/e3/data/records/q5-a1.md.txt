### red-team

> OPTION: Approve with further amendments
> 
> The prior Council's amendments are mostly sound, and the shape is right. Software keeps the hard gate, and the closed allow-list with fail-closed classification is the correct design. Three gaps are still open, and each can widen authority in practice.
> 
> 1. The deferral argument in OD-1 is only half true. Unlisted or scripted files are Software, which is safe. But the allow-list includes decks and PDFs, and the spec defers the content check that tells a "non-scripted" deck or PDF from a macro-bearing one, along with MIME sniffing. Until those exist, the classifier cannot honestly place a deck or PDF in the Artifact class. The fix is to make PL1 treat decks, PDFs, SVG and HTML as Software until the check ships. Only plain documents, raster images, audio and video should be Artifacts at first. A magic-byte check should be mandatory for those, because extension-only classification lets a renamed script through.
> 
> 2. "Markdown is always allowed" is too broad. Markdown is loaded as instructions in many places, including outside the governed paths. Examples are AGENTS.md, CLAUDE.md, command and prompt folders, and README-style files that agents read. Section 2.1.1 lists only five governed paths. A write to a Markdown file that another agent later reads as instructions is a trust-raising write. I would state that any Markdown a role or harness loads as instructions is Software or governed, derived from the loader registry rather than from the extension.
> 
> 3. The log's attribution is only as good as its link to the operator prompt. The daemon writes the log, but section 3 never says how it knows which operator prompt caused a write. If the agent supplies the task id or the prompt reference, it can attribute its own write to a benign prompt. The daemon must bind each entry to the prompt it received from the operator channel, not to anything the agent passes in. The hash chain is also local and unanchored, so a host-level actor can rewrite the whole chain. State that tamper-evidence is partial, or anchor the chain head in the daemon audit log.
> 
> Smaller points:
> - "Verbatim" conflicts with "secret scrubbing before write". Say that redaction is the one allowed deviation and mark the redacted spans.
> - No retention rule exists yet, although the log stores pasted secrets. At minimum, set a default expiry and exclude the log from bundle export in code. That is the stated default, but it needs a test.
> - AC-8 should cover a PDF with JavaScript and a renamed-extension case.
> - AC-6 should test that the daemon rejects a forged task id (see point 3).
> 
> Answers. D-1: daemon-only local/ log, as drafted. D-2: specs/external/<project>/, which keeps the authorizing spec out of the external repo's control. D-3: no (system) entries, which is correct. It keeps the log operator-only, and the daemon audit log covers non-operator work.
> 
> Risks
> - The artifact exemption becomes the easiest bypass for code, for example code smuggled in a "document" or a deck.
> - Instruction-bearing Markdown is poisoned under the "always allowed" class.
> - The log gives false audit assurance if prompt binding is weak.
> - Edits made outside Delphi are unlogged. The spec states this, but operators may still treat the log as complete.
