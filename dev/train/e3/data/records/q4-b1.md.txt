## Round 1 stances (blind)

### architect

> OPTION: One schema, two entry paths
> 
> **Reasoning**
> 
> Keep a single schema and give summaries their own kind. That avoids two parallel stores and makes linking trivial. Two entry paths feed it, and they differ only in who performs the act and what trust that act earns.
> 
> **Schema.** Frontmatter: `kind: summary | atomic`, `id`, `author`, `source_type` (daemon-computed), `summarizes: [entry ids]`, `sources: [urls/paths]`, `retrieved`, `validation: none | validated | disproved`. A summary is a document, not a claim. Its `validation` is `none` by default and is never inferred from the operator importing it.
> 
> **Path A: operator import.** `delphi kb import <file.md>` and a TUI import action are the same code path. This is one step. The daemon reads the file, computes taint from the file's provenance, scrubs it (secrets, local paths), and writes it to the KB with `kind: summary`. The import act counts as ratified-for-inclusion. The trust tier is `user_ratified` for "the operator chose to keep this". It is explicitly not a claim-validity tier. kb_search shows a persistent label such as `[summary · operator-imported · unvalidated]`. Facts inside it are never returned as `<fact>` elements.
> 
> **Path B: agent propose.** `propose_kb_entry` accepts `kind=summary` with a markdown body. It goes to the L0 inbox under t_0001 rules: excluded from search, per-entry ratification, caps and dedupe. Ratifying it is the same operator act as an import, so one ratification flow serves both.
> 
> **Watched folder.** Drop files into `kb/inbox/`, where they are auto-staged only. This is a convenience over Path B, never auto-ratified. I'd defer it. `import` is already one step, and a watcher adds a filesystem-trust surface for little gain.
> 
> **Linking.** Summaries point down to atomic ids via `summarizes`. The daemon derives the reverse index, so atomic entries show "covered by summary X". Dangling ids are flagged. If a summarized atomic entry is later disproved, the summary is marked stale with a banner.
> 
> **Search.** Summaries are searchable and visible, ranked separately from facts. The default query returns facts first and summaries in a distinct group. Search results must never let a summary's text pass as validated.
> 
> **Risks**
> - Laundering: an operator import could be mistaken for validation, or an agent summary could smuggle unvalidated claims in under `user_ratified`. The mitigation is that the tier covers inclusion only, with a persistent label.
> - A summary built from tainted sources inherits the lowest taint of its inputs. The label must show that, otherwise `user_ratified` hides it.
> - Prompt injection in imported markdown. Summaries are data, never instructions, and loading one lowers the task's trust ceiling.
> - Staleness drift when the atomic entries change.
> - Large files bloating context. Impose a size cap and return excerpts, not whole pages.

### red-team

> OPTION: Explicit import with strict taint inheritance
> 
> ### Reasoning
> Agent-generated markdown summaries pose a classic Trojan horse vector for Knowledge Base poisoning. When operators import multi-page documents, they inevitably skim rather than audit every factual claim, creating a high-risk laundering channel where untrusted or hallucinated claims bypass the L0 verification gate under the guise of an "operator action."
> 
> To keep the system defensible:
> 1. **Reject watched folders:** Automatic ingestion from watched directory paths creates TOCTOU races, partial-write ingestion, and privilege escalation vulnerabilities where any unsandboxed or rogue process dropping a `.md` file triggers KB ingestion. All additions must be explicit.
> 2. **Unified staging schema:** Both operator CLI/TUI imports (`delphi kb import`) and agent submissions (`propose_kb_entry`) must target the same L0 staging inbox and share frontmatter: `kind: summary`, `sources: [entry_ids]`, `taint`, and `status`. 
> 3. **No taint laundering:** Operator import signifies consent for *inclusion*, never *factual validation*. In accordance with Governance §4.3, taint must be computed deterministically from the cited sources. If an imported summary cites unvalidated claims or lacks provenance headers, its taint is capped at `external_untrusted` or `internal_generated`. Under no circumstance does an operator shell command unilaterally raise factual trust to `user_ratified`.
> 4. **Fenced search visibility:** Summaries returned by `kb_search` must be isolated from atomic facts, delivered inside bounded `<summary_document status="unvalidated">` XML blocks, and trigger automatic taint downgrades in consuming agents' context windows.
> 5. **Bidirectional verification linking:** A summary cannot exist in isolation; it must reference atomic KB entry IDs. If any cited atomic fact is later disproved or downgraded, the daemon must mark the summary stale.
> 
> ### Risks
> 
> 1. **Rubber-Stamp Taint Laundering (Failure Scenario):** An operator exports a 2,000-line LLM research note containing subtle prompt injections or fabricated claims and runs `delphi kb import research.md`. Because it was "operator-imported," downstream agents treat it as verified ground truth.  
>    *Remediation:* The daemon inspects frontmatter and content origins; untrusted or unverified summaries retain an immutable taint ceiling and inject taint into any consumer's span.
> 
> 2. **Search Flooding & Attention Starvation (Failure Scenario):** Bulky markdown summaries dominate embedding and keyword search results, displacing precise atomic facts and causing "lost in the middle" degradation in planning agents.  
>    *Remediation:* `kb_search` defaults to returning atomic claims; summaries require an explicit parameter (`include_summaries=true`) or are returned as lightweight pointer cards.
> 
> 3. **Stale Roll-Up Drift (Failure Scenario):** Atomic claims referenced in a summary page are invalidated during a later mission, but the summary text remains untouched, presenting contradicted data as historical consensus.  
>    *Remediation:* Deterministic check (`delphi check kb`) fails validation if a summary links to disproved atomic claims or missing provenance IDs.

### strategist

> OPTION: One schema, two doors, summary kind
> 
> **Reasoning (scope/ROI view):** The smallest thing that satisfies the operator is Option 1 (operator import) built on Option 3's shared schema. Options 2 and 4 are cheap add-ons, not core. Ship in that order.
> 
> 1. **Ingest:** `delphi kb import <file.md>` is the primary path, and the TUI import is a front end on the same command, as in t_0001. It is one step. The operator act counts as ratification of *inclusion* only. Skip the watched folder in v1. It adds a daemon watcher, new failure modes and a second staging surface, and it is the same as the inbox with extra steps. Revisit it only if people actually ask for it.
> 
> 2. **Typing:** add one frontmatter field, `kind: atomic | summary`, with a default of atomic. Summaries are never treated as claims. They get no validated/disproved status and show the label "summary, not claim-validated". Keep the status vocabulary the existing one (validated, not validated, disproved) and don't add new tiers.
> 
> 3. **Provenance and taint:** the daemon computes taint, as in t_0001. A file handed over by the operator records `author: operator`, `imported_by`, and the content hash. Its taint is still derived from what the file contains. The daemon can't know what went into an agent-written file, so a file that declares no sources is treated as `external_untrusted` or `internal_generated` at most, never `user_ratified`. Operator import raises inclusion status only. Per H-004, it must never promote the file's content into heuristics, lessons or skills. Imported summaries are therefore excluded from promotion paths, and this is enforced in code.
> 
> 4. **Linking:** `sources:` lists atomic ids, which gives backlinks. Treat these as unverified pointers, and flag dangling or changed ids at search time. A summary does not inherit its sources' validation. Staleness is shown when a source entry's hash changes.
> 
> 5. **Search:** searchable immediately once imported, but the result carries a visible kind label. Rank atomic entries above summaries by default, with a `kind` filter available. This keeps a confident-sounding roll-up from outranking the evidence it summarizes.
> 
> 6. **Agent path:** `propose_kb_entry kind=summary` goes through the same L0 inbox and per-entry ratification as before. It adds no new mechanism.
> 
> **Risks:**
> - Laundering: a summary is read as authoritative and the claims in it never get checked. Mitigation: the label, the rank order, and the promotion block.
> - An operator importing a poisoned or injected file. Treat the body as data, scrub it, and apply size caps.
> - Summary drift when sources change. Mitigation: hash-based stale flags.
> - Scope creep into a document management system. Limit v1 to markdown, one command and one kind field.
> - Label fatigue: if every result is labeled, nobody reads the labels. Keep the label to one short tag.

## Verdict

**Escalated to the operator:** 1 unresolved P0 finding(s).

All seats (architect, red-team, strategist) recommend PROCEED-WITH-CHANGES; the open items below need your sign-off.

> The Council recommends one shared schema with two doors. Operator import (`delphi kb import <file.md>` and the TUI, one code path) and agent propose (`propose_kb_entry kind=summary`, which stays in the L0 inbox) both feed it. The schema adds `kind: summary | atomic` (default atomic), `summarizes`/`sources` ids, content hashes, `retrieved` and `author`. The seats also agreed on the following:
> 
> - **Inclusion versus validity:** operator import ratifies inclusion only, recorded as a separate field. A summary is a document, not a claim, so it never gets validated status and is never emitted as a `<fact>`.
> - **Promotion block:** summaries are blocked in code from heuristics, lessons, REVIEW and skills.
> - **Search:** summaries appear in a separate, lower-ranked group with a short persistent label, as bounded excerpts. Loading one lowers the consumer's trust ceiling.
> - **Staleness:** the daemon derives backlinks and flags a summary stale when a source changes or is disproved.
> - **Import safeguards:** size cap, scrubbing, dedupe, and a preview showing computed taint at confirm time.
> - **Watched folder:** deferred in v1. If added, it only stages.
> 
> The Council did not settle one point: which tier an imported summary carries. Architect's opening stance gave it `user_ratified` for "operator chose to keep this" and then conceded the P1 in Round 2. Red-Team holds that any such assignment launders trust. The open question is whether the operator accepts the stricter rule. Under it, taint stays daemon-computed, undeclared sources cap at `internal_generated`, and inclusion is a separate field. The alternative is a looser tier for convenience.
> 
> Strategist and Red-Team also differ on whether a `delphi check kb` command belongs in v1 or is scope creep. Red-Team wants hiding behind an opt-in; Strategist wants a visible group.

## Decision and next steps
