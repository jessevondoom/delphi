### red-team

> OPTION: Approve with amendments
> 
> ### Reasoning
> Spec 070 appropriately separates deterministic software construction from dynamic artifact authoring and ephemeral scratch work, preserving *No Spec, No Build* (§1.3) where architectural drift threatens system integrity. However, carving out exemptions for "artifacts" and "scaffolds" introduces significant attack surfaces if boundary checks rely on nominal extensions or trust rather than deterministic inspection. 
> 
> An artifact exemption without strict active-content sanitization creates an immediate bypass around software build gates. To approve spec 070 safely, amendments must establish:
> 
> 1. **Active Content Invariant:** Exempt artifacts (HTML, SVG, decks, docs) must be deterministically inspected by `delphi-core` to guarantee absence of active scripts, event handlers, iframe injection, macro code, or polyglot payloads unless explicitly routed through Red-tier review.
> 2. **Execution Boundary Integrity:** Un-specced files in `scratch/` or scaffolds must be strictly non-executable. The runtime must block execution on the host outside the hardened sandbox (§5.5).
> 3. **Tamper-Proof Audit Logging:** The prompt log must be immutable from the perspective of agent execution spans to prevent retroactively fabricated provenance.
> 
> With these controls and the resolutions for D-1, D-2, and D-3 detailed below, the spec balances operational fluidity with rigorous governance.
> 
> ### Decisions
> - **D-1 (Log Location):** Store the log in `.delphi/audit/operator-prompts.jsonl` (daemon-owned, outside agent-writable workspace paths). The daemon must hold an append-only file descriptor that agent file-mutation tools cannot truncate, overwrite, or delete.
> - **D-2 (External Project Spec Location):** Standardize strictly on `specs/external/<project>/` within the primary governed Delphi repo. External specs must remain Tier 2 artifacts subject to ratification (`ratified.lock`), preventing external projects from silently bypassing spec review.
> - **D-3 (Log `(system)` Entries):** Disallow unqualified `(system)` entries. All entries must carry explicit origin tagging (`origin: operator` vs. `origin: system:<subsystem>`) with daemon-issued nonces. System-generated triggers must never be credited as human operator prompts.
> 
> ### Risks, Failure Scenarios & Remediations
> 1. **Risk: Polyglot Active Content in Exempt Artifacts**
>    - *Failure Scenario:* An agent authors an SVG diagram or HTML deck containing embedded JavaScript, iframe exfiltration vectors, or malicious CSS to execute code in the operator's viewing environment without triggering software spec scrutiny.
>    - *Remediation:* Mandate AST/DOM sanitization in `delphi-core` for all exempt formats prior to disk write, stripping script blocks and active attributes unless accompanied by a Red-tier gate.
> 2. **Risk: Tooling Bootstrap via Scratch Escape**
>    - *Failure Scenario:* Builder writes executable Python/shell scripts into `scratch/` or scaffolding directories, executing them on the host to implement un-specced functionality.
>    - *Remediation:* Enforce `noexec` invariants on `scratch/` paths and fail any build step attempting to execute untracked or un-specced scripts outside an isolated OS container.
