## Round 1 stances (blind)

### architect

> OPTION: One schema, two entry paths
> 
> **Reasoning.** Architecturally the simplest design is one record type with a `kind` field and two doors in, differing only in who performs the act. The options are not exclusive; the choice is how to combine them without a second trust model.
> 
> 1. **Schema.** Every KB item has frontmatter: `kind` (`claim` | `summary`), `id`, `sources` (list of atomic ids or URLs), `retrieved`, `author`, `source_type` (taint), `ratified_by`, and `validated` (`none` | `validated` | `disproved`). Summaries link downward through `sources: [id…]`. Atomic entries need no back-pointer. The daemon derives "summarized-by" at index time, so there is no double bookkeeping and no stale links.
> 
> 2. **Operator import (`delphi kb import <file.md>`, TUI drag-in).** One step. The act records `ratified_by: operator` for inclusion only. Taint is computed from the file's content origin as the daemon sees it: a hand-written file is `user_ratified`, but an agent-authored file the operator forwards keeps the taint of its provenance if the frontmatter or header shows it. The daemon refuses to let the operator's act launder it into claim-validity. `validated: none` is always the default, and a summary is never `validated` unless its claims go through `validate_claims`. It is searchable immediately, with a visible label such as `[summary · operator-imported · unvalidated]`.
> 
> 3. **Agent path.** `propose_kb_entry(kind=summary, body)` goes to the same L0 inbox, excluded from search until per-entry ratification. Ratification grants inclusion only, as above. The caps, dedupe and scrubbing from t_0001 apply unchanged, plus a larger body cap for summaries.
> 
> 4. **Watched folder.** I would not make it a third door. It is the same as import, but with ambient authority: a drop could come from any process that can write the folder, including an agent. If it exists, it stages into L0 only (never auto-ratified) and is needed only as a convenience. I would defer it.
> 
> 5. **Search.** Default `kb_search` returns both kinds, with `kind` and `validated` shown on each result. Support a `kind=` filter. Rank atomic validated claims above summaries on ties, so a roll-up never outranks the facts it rests on.
> 
> 6. **Trust rule.** A summary's effective trust is the minimum of its own taint and its sources' taint. It cannot feed promotion into heuristics, lessons or skills (H-004), whatever the operator's import did.
> 
> **Risks.**
> - Operators read the "searchable" label as "true". Mitigation: the label is mandatory and cannot be hidden.
> - Imported files carry prompt-injection text. They are indexed as data and retrieved with a data fence, and the import step scrubs secrets and local paths.
> - Stale summaries drift from their sources. Flag a summary when any source is disproved or withdrawn.
> - Large files dilute retrieval, so chunk them with the parent id retained.
> - A watched folder lets agents bypass the staging gate.

### red-team

> OPTION: Explicit import with strict taint preservation
> 
> Ingesting aggregate Markdown summaries introduces a significant memory-poisoning and injection surface if provenance boundaries are blurred. Summaries bundle dozens of implicit assertions into unstructured prose, making atomic verification impossible.
> 
> To safely accommodate operator ergonomics while preserving anti-poisoning invariants:
> 
> 1. **Reject Watched Folders:** Automatic ingestion from a watched workspace folder must be forbidden. Any rogue build script, hijacked subprocess, or untracked tool could drop files into the inbox, bypassing intent. All ingest must be explicit: CLI (`delphi kb import <file.md>`), TUI explicit drop, or daemon-mediated `propose_kb_entry`.
> 2. **Inclusion Does Not Launder Taint:** An operator-initiated import grants authorization to store and index (`user_ratified_inclusion`), but explicitly **not** epistemic truth (`validation="not validated"`). The file's frontmatter must record the originating generator or author. If an agent authored the file, the daemon must compute taint based on the session's lowest input tier, preventing the operator command from acting as an inadvertent taint-cleansing proxy.
> 3. **Strict Structured Schema & Atomic Pointer Links:** Summary files must enforce a rigid frontmatter schema (`kind: summary`, `author`, `taint`, `sources: [<entry-id>]`). Summaries must cite the atomic KB IDs they synthesize. If an underlying atomic claim is disproved or marked stale, dependent summaries must be flagged for review.
> 4. **Isolated Search Visibility:** Full-text dumps of unverified summaries in `kb_search` create context-stuffing and prompt-injection risks. Summaries must return only metadata, high-level abstracts, and explicit taint warnings in general search; full markdown bodies should require explicit opt-in reading.
> 
> ### Risks
> 
> - **Taint Laundering via Operator Habituation:** Operators will routinely run `delphi kb import` on agent-generated research outputs. Downstream agents may treat operator-imported files as verified truth (`user_ratified`) unless the runtime strictly isolates inclusion status from claim validation.
> - **Indirect Prompt Injection:** Adversarial or hallucinated directives embedded within long Markdown summary bodies can poison agent reasoning when pulled into future contexts.
> - **Silent Contradictions:** Summaries decoupling from atomic KB entries allow disproved facts to persist indefinitely inside frozen prose roll-ups.
> - **Staging Bypass:** Permitting a watched folder creates a local privilege escalation path where untrusted background tasks inject synthetic memory directly into Delphi.

### strategist

> OPTION: One schema, two entry doors
> 
> **Reasoning (strategist: scope, sequencing, ROI):**
> 
> The host offers four options that are really two doors (operator import, agent propose) plus a shared schema plus a watched folder. Build the shared schema first, because it is what everything else rests on. Then ship the operator door. Defer the rest.
> 
> **Sequencing**
> 
> 1. **Phase 1: shared schema plus operator import.** Add `kind: summary | atomic` to the frontmatter, plus `sources: [entry ids]`, `author`, `retrieved`, and a computed `taint`. Add one command, `delphi kb import <file.md>`. The TUI drag-in is the same code path, so it is a thin front end and not separate work. Import is one step. The operator's act means "include this", so the file skips L0 and is searchable at once. That matches the stated friction goal.
> 2. **Phase 2: agent-submitted summaries.** Let `propose_kb_entry` accept `kind=summary`. It goes through the same L0 inbox and per-entry ratification that t_0001 already set up. This costs almost nothing, since the staging path exists. Agent summaries are never auto-visible.
> 3. **Phase 3, only if asked for: watched folder.** It is the weakest ROI. It adds a new ingress surface, a file watcher, and a lot of dedupe and scrub noise. `import` already costs one command, so the folder saves very little. Cut it for now.
> 
> **Trust semantics**
> - Operator import raises the status to *included*. It does not raise it to *validated*. Show a visible label such as `summary · operator-included · claims not validated`. Taint is still computed from the inputs. Ratifying inclusion must not change the claim-validity tier, because a summary built from untrusted sources is still low-trust.
> - Search returns summaries with the label, and filters by `kind`. By default, rank atomic entries first and show summaries as navigational context.
> - Links are by id. A summary lists its source ids, and a back-reference index is derived and not hand-maintained. If a source entry is disproved or withdrawn, flag every summary that cites it as stale. That is the one piece of maintenance work worth building.
> 
> **Risks**
> - **Laundering:** a summary of unvalidated claims, once included, reads as authoritative. The label and the stale-flag mitigate this, but only the daemon can enforce it. A prompt cannot.
> - **Promotion leak:** an included summary must stay below `internal_empirical` for H-004, so it can never feed heuristics, REVIEW or lessons without separate verification.
> - **Injection:** imported markdown is untrusted text. Scrub it, and treat its contents as data when it is read.
> - **Scope creep:** the watched folder and the encyclopedia-style generation tooling are separate asks. Keep them out of this change.
> - **Schema drift:** if the summary's `sources` ids can dangle, links rot silently. Validate them at import.

## Verdict

**No deterministic escalation:** no unresolved P0 and the Round 2 recommendations agree. The decision is the operator's.

> The Council recommends options 1, 2 and 3 together: one schema with two entry doors. It rejects the watched folder.
> 
> **Schema.** Every entry carries `kind` (atomic or summary), `id`, `sources` (atomic ids), `retrieved`, `author`, a daemon-computed taint, and `validated`, which defaults to none. Summaries link down by id. The daemon derives the back-index.
> 
> **Operator door.** `delphi kb import <file.md>` and the TUI drop are the same code path and take one step. The operator's act ratifies inclusion only. It never ratifies claim validity and never raises taint. A summary's effective trust is the minimum of its own taint and its sources' taint, and it can never feed H-004 promotion.
> 
> **Agent door.** `propose_kb_entry(kind=summary)` goes through the existing L0 inbox with per-entry ratification and a larger body cap.
> 
> **Visibility.** Search shows a mandatory, non-hideable label such as "summary · operator-included · claims not validated". It supports a `kind=` filter and ranks atomic entries first. Bodies are scrubbed at import and returned inside a data fence.
> 
> **Agreed.** All three seats agreed on the shared schema, on inclusion not equalling validity, and on cutting the watched folder (Red-Team and Strategist want it rejected outright). They also agreed on validating source ids at import and flagging stale summaries.
> 
> **Disputed.**
> - *Provenance:* Red-Team wants files with no daemon provenance to default to low taint. Architect would infer taint from file content. I side with Red-Team and Architect's P3: unknown origin means low taint unless the operator attests authorship with an explicit flag.
> - *Retrieval:* Red-Team wants summary cards only, and Strategist calls that too costly. I recommend cards by default, with a full-body read as one explicit call.
> - *Stale summaries:* Red-Team wants them excluded from default search. I agree.

## Decision and next steps

**Decision:** Build the shared schema with the operator import door first, then agent-submitted summaries via the L0 inbox, with no watched folder.

1. `architect`: Draft a spec for the summary schema, taint rules (unknown origin defaults low, plus an attestation flag), source-id validation, stale quarantine, and card-first search.
2. `red-team`: Review the draft spec against the open P1 items on provenance laundering, injection, and lineage.
3. `builder`: Implement `delphi kb import` and the TUI drop on one code path once the spec is approved.
