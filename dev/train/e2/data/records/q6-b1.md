### red-team

> OPTION: Approve E1-E2 only; defer installer, launcher
> 
> Spec 071 provides valuable standardization for host-agent MCP discovery, but bundling executable launcher scripts and host-level configuration mutation into the initial release introduces severe attack surfaces that violate Delphi's core isolation invariants.
> 
> D-1 (drift-tested `ecosystem/` folder and `marketplace.json`) is sound and acceptable, provided it remains strictly declarative metadata validated deterministically by CI against an authoritative schema.
> 
> D-2 (`delphi mcp --install` editing host config files outside the workspace) and D-3 (launcher scripts in plugins) represent unacceptable authority widening. Under GOVERNANCE §5.1, §5.4, and §5.5, workspace isolation and process containment are non-negotiable. Allowing an automated command to mutate external host configuration files (e.g., `~/.claude.json` or Claude Desktop configs) creates an external mutation path that can silently alter host security postures, inject unvetted MCP endpoints, or corrupt existing host setups. Automated external file mutation must be deferred; Delphi should generate explicit, reviewable diff snippets that the operator manually inspects and applies.
> 
> D-3 is a critical security vulnerability and an absolute blocker. Permitting executable launcher scripts within plugin packages transforms static configuration into an arbitrary code execution vector executing unsandboxed on the operator's host. A compromised or poorly audited plugin could execute arbitrary shell commands, exfiltrate host environment variables and credentials, or establish persistence. Plugins must remain purely declarative configurations pointing to pre-existing, trusted binary paths on the system.
> 
> Approving E1 and E2 allows catalog schemas and static exports to mature safely. Deferring E3 (installer) and E5 (launcher scripts) prevents premature authority expansion before rigorous sandboxing and cryptographic verification are established.
> 
> ### Risks
> 
> 1. **Arbitrary Code Execution via Launcher Scripts (D-3)**:
>    - *Failure Scenario*: A tampered marketplace plugin bundles a launcher script executing outside any sandbox, running arbitrary commands with full user permissions upon host tool initialization.
>    - *Remediation*: Ban executable launcher scripts entirely. Restrict plugins to declarative schemas defining verified binary paths and static arguments.
> 
> 2. **Host Configuration Poisoning and Tool Injection (D-2)**:
>    - *Failure Scenario*: `delphi mcp --install` writes outside the workspace boundary, silently modifying global host configuration to register rogue MCP endpoints or clobber user settings.
>    - *Remediation*: Restrict the installer to emitting validated diffs/snippets for manual operator application. If automated later, require interactive confirmation with atomic backup and rollback.
> 
> 3. **Unauthenticated Marketplace Supply Chain (Q-1–Q-5)**:
>    - *Failure Scenario*: Host agents load unpinned or unsigned marketplace plugins, exposing the host agent to prompt-injection or tool-spoofing attacks from untrusted external sources.
>    - *Remediation*: Require cryptographic signing and immutable content hashing for all marketplace plugin manifests before enabling automatic resolution.
