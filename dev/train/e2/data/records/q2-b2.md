### red-team

> OPTION: Close gaps via new tools/resources
> 
> ### Reasoning
> 
> From a red-team perspective, attempting to close these architectural gaps through "prompts and plugin guidance only" violates core governance invariant §5.6 (*Enforcement Is Code, Not Prose*). Unenforced prompt instructions sent to a host agent cannot guarantee safety, role boundaries, or security invariants. 
> 
> 1. **RAG & Knowledge Retrieval (Spec 064):** Relying on prompt steering to query the knowledge base invites prompt injection, taint laundering, and context window pollution. Delphi's Information Flow Control (IFC) lattice (Governance §4.3) requires taint to be computed deterministically by the runtime, never declared or steered via prose. Exposing scoped, read-only MCP resources and query tools with explicit trust-tier metadata is required to prevent untrusted external inputs from masquerading as verified facts.
> 2. **Specialties & Role Routing (Spec 041):** Prompt-emulated personas suffer from role blurring (`FM-1.2`) and sycophantic convergence. A host agent cannot replicate Delphi's adversarial counterweights without deterministic dispatch endpoints that enforce role contracts, blind-round limits, and orthogonal model families (`[H-001]`).
> 3. **Spec-Driven Governance (Specs 013/062):** "No Spec, No Build" (§1.3) and drift remediation cannot be policed by client-side prompt reminders. If the host agent can mutate code without interacting through a governed spec-check/gate tool, spec-implementation drift (`FM-1.1`) is inevitable.
> 
> Therefore, Delphi must expose dedicated, bounded MCP tools and resources—specifically for structured retrieval with taint metadata, role consultation/dispatch, and deterministic spec verification—rather than relying on permissive, unvalidated host prompts.
> 
> ### Risks
> 
> 1. **Confused Deputy & Tool Poisoning:** Exposing new MCP dispatch and retrieval tools broadens the ingress surface. Malicious context in retrieved data could manipulate the host agent into executing unintended high-privilege Delphi actions.
> 2. **Taint Lattice Evasion:** If the host agent aggregates Delphi MCP outputs and echoes them back without preserving computed taint tiers, memory anti-poisoning defenses (§4.3) fail.
> 3. **Scope Creep & Surface Bloat:** Proliferating fine-grained MCP tools risks cognitive overload for the host LLM, increasing tool-calling error rates and unhandled edge-case failures.

The cheapest close is MCP prompts and resources: spec templates, the review rubric, the `check` kinds, and a spec lifecycle walkthrough. Add one tool only if a host can't already list specs and their approval status.

> **Rule for deciding:** write a tool only when a host cannot do the job through retrieval, a resource or a prompt.

> 
> **Risks:**
> - **Mutating tools exposed to hosts.** Writes, dispatch and outbound actions over MCP widen the attack surface. Everything new should be read-only, or approval-gated like today's Red-tier actions.
> - **Taint and trust flattening.** Host agents may drop the tier and validation labels, so unvalidated leads get presented as fact. Labels should be part of every result.
> - **Overreach.** Four goals can turn into a rebuild. Cap each to one slice and one verification.
> - **Spec drift.** Tools added without amending 062 or 064 break "No Spec, No Build".
> - **Unverified premises.** This ruling rests on specs I couldn't read. The audit should confirm it before anyone builds.
