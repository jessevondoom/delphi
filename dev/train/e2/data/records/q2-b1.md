### red-team

> OPTION: Close gaps via new tools/resources
> 
> Delphi's current MCP surface falls dangerously short across all four domains when accessed by an external host agent. Declaring the surface sufficient is blind complacency; attempting to paper over the gaps with prompts and plugin guidance directly violates Governance §5.6 ("Enforcement Is Code, Not Prose"). Host LLMs systematically ignore prose guidelines, hallucinate role boundaries, and drop security invariants.
> 
> The gaps must be closed by discrete, schema-enforced MCP tools and resources:
> 
> 1. **RAG & Knowledge Retrieval (Specs 062/064):** `kb_search` and `xenia_search` return disconnected passages, leaving synthesis to an unconstrained host that cannot track taint. Without an MCP-exposed semantic slice resource that carries computed taint metadata and provenance frontmatter (`[H-004]`), the host treats unvalidated leads as established facts, exposing the system to memory-poisoning and prompt injection.
> 2. **Agent Specialties & SME (Specs 041/003):** The host currently has no tool to dispatch queries to canonical roles (e.g., `consult_role` or `delphi_ask_agent`). An external agent attempting to "roleplay" Architect or Red-Team in its own context destroys the counterweight architecture (§2), creating single-model sycophancy and correlated blind spots (`[H-008]`).
> 3. **Research Reporting & Strategy (Specs 013/038):** While reporting artifacts exist, strategy synthesis lacks a structured interface. The host cannot invoke bounded, multi-family Councils or retrieve Strategist roadmap validations without a dedicated Council-query MCP tool.
> 4. **Spec-Driven Guidance:** The host can write files but cannot deterministically verify them against base-branch rubrics or check merge gates. Expanding `mcp_delphi_delphi_check` to validate spec invariants, task contracts, and drift detection over MCP is mandatory to prevent uncontrolled, off-spec implementations (*No Spec, No Build*, §1.3).
> 
> **Risks:**
> - **Taint Lattice Inversion:** Ingress from external host agents is L1/untrusted. Exposing internal roles without hard capability gates and automated taint computation risks promoting unverified host outputs into ratified memory (`[H-004]`).
> - **Correlated Council Collapse:** If a host agent orchestrates pseudo-councils locally rather than routing through Delphi's heterogeneous runtime, it violates `[H-001]`, yielding zero adversarial tension.
> - **Privilege Escalation via Host Tool Chaining:** Granting external hosts write or dispatch tools without synchronous operator gates (§5.4) allows untrusted host loops to trigger destructive actions.

> 5. **P4: Research and strategy reporting (goal 3).** Reuse the existing request-research and report-writing flows. Council and research runs already require operator approval, so keep that.

> **Scoping rule:** every added tool needs a named goal, a measurable "done" check, and must be read-only or approval-gated. Nothing may let a host agent bypass ratification, taint rules or Red-tier gates. Taint is the sharpest point: content returned through MCP to an outside host should carry its tier labels. The host's reply is advice and must not become promotion input.
> 
> **Risks**
> - I'm ruling on specs I couldn't read, so the gaps may already be closed or may differ from what I've assumed.
> - Tool sprawl and gold-plating, if each goal gets its own tool without the matrix.
> - Authority leakage, if a host-facing consult or dispatch tool lets outside agents trigger spend or mutations.
> - Unlabeled retrieval leaking low-trust content into the host as if it were validated.
> - Prompt-only fixes that read as complete but enforce nothing, which is the premature-victory failure mode.
