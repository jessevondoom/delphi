# Changelog

What changed in each release, newest first. Delphi is pre-1.0: minor versions may change commands and formats, and the notes say so when they do. The `dev` tag is a rolling build of `main`, made on request (`delphi update --dev`).

Release builds, with their notes and build attestations, are on the [releases page](https://github.com/jessevondoom/delphi/releases). Entries that cite a pull request (`#nnn`) refer to this repository's pull requests.

This file starts with the work after v0.2.7. For earlier releases, the history is the merged pull requests and the per-spec notes under `specs/`; their entries below give dates, not detail.

## Unreleased

- Brighter role colours on light backgrounds, still WCAG AA: each role now has a light text colour (its name and glyphs; 4.5:1 on white, cream and the desktop app's light surfaces) and a brighter light fill (chips and bars; 3:1 as a graphic, a dark face on it 4.5:1). The avatar table sends both (`chassis_light`, and the new `chassis_light_fill`), `role_fill_light` joins `role_look_light`, and the Claude Code theme uses the fill on a light preset. Every light colour changes (the orchestrator's from `#7e22ce` to `#8f23f3`, for one); run `delphi connect claude-code --theme` again to refresh a light theme file.
- The desktop app (spec 111, slices A0 to A8; not in a release yet): `app/` holds a window that shows the daemon's state and changes nothing. It attaches on the read-only narrator scope only, can name nine daemon methods (all reads on the narrator allowlist) and five reads of the knowledge base, opens no port and never starts a daemon. Screens: Activity (what agents said, read and recorded, the roster, what waits on you), Councils (seats, positions and critiques, the council's activity while it runs, the verdict; a blind round's words are never shown), Knowledge base (search, the shelf, a reader with provenance), Work output (grouped by what the project produced, in a list or a grid), Agents and skills, and Settings. Warm-grey dark and light themes that follow the system. An agent is always a chip, its name in bold in its colour and its role in grey. Markdown is drawn in full (tables, task lists, quotes, pictures beside a document), a document's front matter is shown as facts and tags, and a deck, a page, a picture or a recording opens in your browser or viewer. Build it with `app/dev/build.sh`, which also runs a smoke test of the built app; the guide is `docs/guides/desktop-app.md`. `delphi daemon where` now sends the active theme's role names (it sent role ids).
- Role colours in Claude Code, exact (spec 106, slice G7): `delphi connect claude-code --theme` shows a plan, asks `[Y/n]` at a terminal, writes a theme that changes only Claude Code's eight subagent colours to the roles' own (`~/.claude/themes/delphi.json`, on the preset you already use) and sets `theme` in `~/.claude/settings.json` to `custom:delphi`, changing nothing else in that file; `delphi connect claude-code` offers it once connected. A custom theme of your own is never switched (the eight lines to add are printed); with `auto` the theme stops following the terminal's background and `--light` or `--dark` picks the base; `--dry-run` only prints and `--remove` puts the earlier theme back. The orchestrator, strategist, architect, scout, red-team and builder now have six different Claude Code colour names (the architect's files change from `cyan` to `blue`, the advocate's from `red` to `pink`). Seen live: Claude Code 2.1.325 draws the line that starts a subagent as its name on a filled background of its colour, and nothing else in colour.
- The session hooks are on by default (spec 105 H5, the operator's decision of 2026-11-14): `[mcp] session_hooks` now defaults to `true`, so an installed Claude Code plugin's hooks print the brief and route mentions without `delphi mcp --hooks on`; turn them off with `delphi mcp --hooks off` (or `[mcp] session_hooks = false`); `[mcp] enabled = false` still silences them.
- Session hooks, the live check (spec 105 H4): a Claude Code session with the plugin and the hooks on showed the brief arriving, a role mention routed, the marker written and a worker loading. It also showed the marker had no counts: Claude Code turns every character other than a letter or digit into `-` in its transcript folder name, and Delphi turned only `/` and `.`. The folder name is fixed, with a test, and `delphi learn ingest` uses the same rule.
- Three label defects the labels experiment found are fixed (spec 109, slice Q8): a host session note's `label` now reads `host session note, not checked` (it read `not validated`); a library page's `source_type: federated_verified` carries `source_type_note` saying it is the library's fixed tier (fetched and stored by Delphi, the content third-party and not checked); and a source added from a local file gets an id from its base name and a hash (`local-<name>-<hash>`), not its absolute path, so a pointer a host is shown names no home directory or user (entries made earlier are still found and are shown redacted). No tier or index changes.
- The orchestrator's compact pack fits its bound (spec 106, slice G1): the orchestrator's manifest marks five blocks that describe Delphi tools a host does not have (the timer, naming threads, system inspection, the `suggest_rule` argument detail and the tool-inventory reading of seats) with `inside-only` markers, which a compact pack drops and which Delphi's own agents never see; a compact pack's skill index lists names only, with a line saying `list_skills` gives the descriptions. Release text and third-party text come back in their own `release` and `third_party` groups (third-party last, short and fenced). Both tools take `use: "verify"` for only validated text from ratified or empirical sources. A new skill, `reading-labels`, says how to weigh each label by task; Delphi's own agents search as before.
- Live checks of the hosts recorded (spec 110, slice X4b): Claude Code 2.1.325, Copilot CLI 1.0.111 and Codex 0.169.0 were run against a temporary Delphi home and spec 110 §8 says, per host, what was shown to work. The guide to other tools is corrected, including which tools need the daemon.

Gemini CLI: one extension folder with the server and `DELPHI.md` as its context file (unverified: Gemini CLI could not be run in the live check). - Live-check scripts for the other hosts (spec 110, slice X4 probe): `dev/hosts/claude-code.sh`, `copilot.sh`, `codex.sh` and `gemini.sh` run each host non-interactively in a scratch project against a temporary Delphi home, configured only by flags and scratch files, at most six model calls each, and print what the host did: the client name it sends, the tool count, the pack's adapter line, its own tool names, which hooks fired and whether a worker file ran. The first results are in spec 110 §8.
- A worker subagent for every role served to hosts (spec 106, slice P3): the Claude Code plugin now carries `<role>-worker` for twelve roles beside the four Panel seats, `delphi plugin export` writes `delphi-<role>-worker` files for Copilot and agy, and `delphi mcp --install codex --agents` writes `delphi-<role>-worker.toml` too. Each is a short wrapper that adopts the role with `get_agent` in its own context, on the session's model; on Claude Code only the builder's and the writer's inherit the session's tools, the others get read tools only. The `delphi` skill says when to adopt a role in place and when to use its worker.
- `get_agent` now serves a compact pack by default (spec 106, slice P2): a verbatim excerpt of the charter with a note on what was left out, and rules without their falsification lines; it is 31 to 41 percent smaller. `detail: "full"` returns the pack as before. Pass the `pack_hash` you hold as `if_hash` and an unchanged pack is one line; `list_roles` lists each servable role's `pack_hash`. The header names the calling host's adapter, and says when there is none (only Claude Code has one); `prompts/get` serves the compact pack with the identity line, and the prompt hook names the compact pack's hash.
- `delphi mcp` serves the operator's ratified charter as the resource `delphi://charter` (never a project's `GOVERNANCE.md`), and can build a verbatim charter excerpt for a role from a fixed table, falling back to the whole charter when the charter's structure no longer matches (spec 106, slice P1; packs use it from P2).
- What the orchestrator mention does is said one way everywhere (spec 107, slice B2): the `delphi` skill, the prompt hook's line and `delphi mcp --print-claude-md` all say to call `consult_orchestrator` with the task first, and `request_help` when the briefing's `next` names it, when you want Delphi's own view or a second opinion, or when the model is unsure which role fits. `request_help`'s description says so too, and `delphi_roster` names the orchestrator by the active theme's name.
- `consult_orchestrator` now reads the task (spec 107, slice B1): the roster comes from the ranking `route` uses (the orchestrator alone when no role fits, with each role's `worker` subagent name), `trigger` says whether it calls for a Panel or a Council, `context_pointers` are the project files that match it and `memory` the orchestrator's memory that does, and `next` suggests up to three tools. A new optional `kind` (`software`, `analysis`, `document`; inferred when left out) keeps a report from being told it needs a spec or `cargo test`: a gate is named only from `done_when` or the project's own `AGENTS.md`. `families` says which model families the running daemon can seat. Every existing key and argument is kept; project and memory text is marked untrusted; the answer is at most 6 KiB.
- Transcript ingest runs with the daemon up (spec 108, slice M3): with the session hooks on and a project opted in (`delphi learn ingest --enable`), Claude Code's session end asks the daemon once to stage notes from that session's transcript (corrections, and tool calls that failed and then worked) at L0, secrets redacted, never twice. The daemon reads only a file of this project's own transcript folder, never through a symlink, at most 32 MiB. The `delphi` skill now asks the model to call `propose_note`, `record_session_summary` and `recall_sessions`. `delphi learn ingest` works as before with the daemon stopped.
- A new host tool, `recall_sessions` (spec 108, slice M1): what the last host sessions of this project left (their summaries, notes and handoff objectives), newest first or ranked by a `query`, never the caller's own session, a note you dropped or kept, or a session that read a private entry. With no project, only sessions started in the same folder are recalled. Every text is cut, fenced and labelled not validated; the answer is at most 8 KiB and never enters a pack, an index or the session brief. `delphi doctor` says how often it was called.
- `search_kb` and `kb_retrieve` now return research entries you kept with `delphi kb review keep` (a `kept` layer), fenced and labelled `kept by the operator, not validated`; pages you imported from outside stay out of host search as before. A kept page carries a new `kept_from:` line naming the entry it came from. `propose_council_record` now says the agenda is saved under `missions/agendas/` for you to read (it is not listed in `/retro`), and `handoff_put` says its default target is the orchestrator (spec 108, slice M5).
- `delphi learn keep <mission>/<id> --as lesson --role <role> | --as rule` keeps a note a host staged: it shows the note and what it will write, and writes only after you type yes at a terminal. A lesson goes into that role's `lessons.md` (workspace scope, or `--scope operator`) and needs a trigger and a directive (`--text "T: … D: …"`); a rule goes into `heuristics.md` the way `delphi customize rule` writes one. Both pass the no-relaxation test and the Rule of 25, record where they came from, and close the note; the command needs the daemon stopped. `delphi learn list` marks host notes reported by two or more sessions and prints the command (spec 108, slice M2).
- The trace harvester now runs: when a daemon task ends, its episode is written to `missions/<id>/traces/<role>-<task>.md` (at most one per task and three per mission) and indexed in the `episodes` zone, which host tools do not search. An episode is stamped from the lowest taint of the task's spans, never above `internal_generated`, and `external_untrusted` when no taint was recorded; before, the harvester was never called and would have stamped `internal_empirical` (spec 108, slice M4).
- `query_memory` no longer returns another role's memory file or another project's mission file: its facets now come from where a file lives (memory, mission, plans) and every result passes the role check `search_memory` applies; `search_memory` refuses a role that is not servable (spec 109, slice Q0a).
- Session hooks for Claude Code (spec 105 H1): the plugin now declares three hooks (`hooks/hooks.json`) that run `delphi mcp --hook <event>`. They printed nothing until you ran `delphi mcp --hooks on` at a terminal (`[mcp] session_hooks`, then off by default; on by default since spec 105 H5). At session start the hook prints a short brief: the team and how to address it, the project's spec names and statuses fenced as data, and a pointer to the last host session with none of its text. `delphi mcp --hooks status` and `delphi mcp --check claude-code` report the hooks file and the switch.
- Mention routing at the prompt (spec 105 H2): with the session hooks on, an `@name` in a Claude Code prompt (a role ID, its themed name or `@delphi`) adds one line telling the model to adopt that role with `get_agent` (with the pack's hash, so a held pack is not fetched again), or to call `consult_orchestrator` first for the orchestrator. Nothing of the prompt is echoed or stored.
- A marker at session end and a summary nudge (spec 105 H3): with the session hooks on, Claude Code's session end writes `local/host-sessions/<tool>-<session>.json` (counts from the transcript, no text; at most 200 kept), the next session's brief points to it, and at the 8th prompt of a session with five or more Delphi calls and no summary the model is asked, once, to call `record_session_summary`.

- A Panel in four calls (spec 104 R5): `council_open` returns every host seat's Round 1 brief; `council_submit` takes a moderator's `stances` for a round, checked whole before any is stored, and answers with `next` (the next briefs, the moderator's brief, or `waiting_on_delphi_seat`); the verdict's answer carries the ruling. A Panel whose Round 1 came in a batch is labelled `relayed`, and counts as an independent review only when the moderator passed a `witness` that the seats ran apart (`counts_as_independent_review`, host-reported). The `delphi-council` skill and the seat files describe the short path first.
- A standing consent for foreign seats (spec 104 R4): `[access] standing_foreign_tokens` (default 0, off) lets `ask_family` and a Panel's foreign seats run without `operator_confirmed` on each call, up to that many tokens per 24 hours. It counts only from the ratified copy of `config.toml`, the check and the reservation are one step, a session that read a private entry still needs the yes, and `delphi doctor` shows the amount and what it used. The answer says which consent it ran under.
- Progress while a host waits (spec 104 R2): a tool call that waits (`ask_family`, `ask_result`, `request_help`, `help_result`, the Council and Panel reads, `council_brief`, `council_submit`, `research_result`) and carries an MCP progress token is sent a `notifications/progress` line every 5 seconds: the daemon's own status line (the phase, or each worker's role, state and time), never agent-written text, and a fixed phrase for a session that read a private entry. Whether a host shows it is not yet observed.
- `delphi mcp` answers requests concurrently (spec 104 R3): up to 8 tool calls run at once, so a waiting call (a help request, a Panel brief) no longer blocks the rest of the session; replies come in completion order. A request the host cancels gets no reply, and an `ask_family` cancelled (or left behind when the host exits) before the host received its `ask_id` has its seat stopped. `delphi bundle serve` stays sequential.
- `ask_family` is a job (spec 104 R1): the call waits up to 45 seconds, then hands back an `ask_id`; the new `ask_result` tool reads the answer once (only the session that asked), `cancel_job` stops it, and the answer now carries a `display` line naming the role that answered, like a help answer.
- `query_memory` no longer returns another role's memory file or another project's mission file: its facets now come from where a file lives (memory, mission, plans) and every result passes the role check `search_memory` applies; `search_memory` refuses a role that is not servable (spec 109, slice Q0a).
- `kb_retrieve`, `search_memory` and `query_memory` now rank the text Delphi's index holds with the same retrieval service `search_kb` uses (hybrid when the index has vectors, keywords otherwise), over an index the MCP server opens read-only; each answer says `ranking: "index"`, or `"words (no index)"` when there is no index. What each tool can return is unchanged. Project text has one word ranker for `search_kb`, `search_project` and `kb_retrieve`, and `kb_retrieve` merges index and project passages by rank; its project passage ids are now 12 hex characters (they could collide before), and its answer starts with a `delphi:rag:meta` line (spec 109, slice Q1).
- Registered projects are now in Delphi's index, each as its own layer: exactly `_index.md`, `specs/`, `plans/`, `context/` and `research/` of the project and its layer's context and knowledge (never the source tree, `work/` or staged notes), always at `external_untrusted`. A session reads only the layer of the project its folder belongs to, and `search_kb`'s core results never include project text. `search_project` and the project parts of `search_kb` and `kb_retrieve` rank from that layer once the daemon or `delphi kb index` has built it, and say `ranking: "words (no index)"` until then; a project that is no longer registered leaves the index at the next refresh (spec 109, slice Q1b).
- A host's `search_kb` now brings the index up to date first when a file is newer than it, as the console's search does, waiting at most 2 seconds; past that it searches what is there and says `index: "stale"`. Its answer and those of `search_project`, `search_memory`, `query_memory` and `kb_retrieve` report `index` (`fresh`, `stale` or `none`) and `index_age_s`; the MCP server's own tools still never write the index. `request_research` refreshes the index when its run ends, so the next `search_kb` finds the pages it kept (spec 109, slice Q2).
- Measured, nothing changed: of the release's 147 documents in the core, context, specs and about zones, a host's `search_kb` can return 17. `GOVERNANCE.md`, `REVIEW.md` and `SPEC.md` index as untrusted and the release's specs and reference sit in the `about` zone, which host search leaves off; spec 109 §9.2 lists the options (spec 109, slice Q3).

## 0.6.1 — 2026-11-13

A summary by spec; the pull requests are listed on the releases page. Nothing in specs 098 to 103 below has been run against a real host, Council, Telegram bot or mailbox yet: the tests use fakes and scratch homes.

- The first `delphi` start in a terminal now asks one question about the history (spec 102, below). Nothing is recorded until you answer it; an answer of no turns the history off.
- The exchange record, a history of your own prompts (spec 102, #668 to #676, #681): on by default, but it records nothing until a person at a terminal has answered the install question. It stores your prompts and capped reply summaries on this machine, with secrets redacted (best effort: some secret shapes may not be masked), pasted blocks as a hash and a length, and short pasted text kept as written; the mission logs keep prompts after a purge. `delphi history off|purge [--since]|delete|status`, the console view `/history`, a daemon timeline, and a citation check on decisions. It never leaves the machine and is never read as an instruction.
- The private-read mark (spec 103, #674, #677 to #680): a task that read a private entry asks you before it sends a web request or a connector call, and a relay or mailbox gets a fixed phrase in place of the text an agent wrote for it. A child task has the same scope as its parent within a session. Only the host's `search_kb` sets the mark today, so Delphi's own tasks are not marked yet.
- Where agents run, host first (specs 098 and 099): Councils run inside Delphi only, and a host that cannot run one gets a labelled unaudited agenda (#617); roles and skills carry a locus (#618); `route` takes any query (#622); research reports its coverage and thin answers in `doctor` (#619); `corroborated` status with an origin count (#623); a claims-based `propose_kb_entry` with a private flag and an egress check (#626, #645); red-team review and `ask_family` (#627, #648); seat states, a stall flag and `cancel_job` (#621); a Round 2 critique is kept when it is valid, Markdown restatements are read, and an unreadable Round 2 is repaired once (#613, #614, #616). The five feature flags added along the way were removed again, with a roll-back plan in spec 098 §13.2 (#642, #653).
- The confidence ladder (spec 100): a tier table, `would_ratify` and a fast lane, a roll-back with a tier audit and a latch, accept-all for vetted claims, a per-tier calibration report, KB-prior tags, and a contradiction step that reads the validated facts (#625, #636, #637, #640, #644, #646, #657, #663). The background validation worker (spec 040 §18.3, #667) is off by default (`[validator] background`).
- Library practice for research (spec 101): a search log for a research run, a local Retraction Watch snapshot and a retraction mark, archived copies read from a web archive as a labelled version, and citation chaining through one pinned index (#635, #651, #652, #655, #658, #664). The lookups send only public URLs or DOIs.
- The merge flow: `delphi merge` judges and records every spec named by trailers (#650) and refuses a bundle across specs (#654).
- Fixed: on a fresh install, the first host `search_kb` no longer fails with `no such table: kb_meta` (#682).
- CI and build, no change to behaviour: package-host outage survival, caches, split Linux tests, shorter test waits, longer limits for the embedding-model jobs (#629, #630, #638, #647, #649, #659, #665, #666).

## 0.6.0 — 2026-11-09

### Shell

- An agent that asked for research with `request_research` is now told how it went, once, at the start of its next turn (and the orchestrator too): counts of pages kept, held for validation or left out, or why it did not start or failed; never page text (spec 058-A10). A failed or cancelled run is logged too, and the outcome goes to the requesting session's log.
- `delphi check fact` now looks up a stored journal page's DOI at doi.org, as the daemon does, so the two agree; `--offline` keeps the text-only check (spec 040-A6).
- New sessions are written under `local/sessions/<id>/` (spec 058-A9); sessions already under `local/missions/` stay where they are and keep working, and every listing, scan and check reads both. Agents still use the `missions/<id>/…` path.
- A `shell` tool: a full shell line for agents, sandboxed when a sandbox is on, otherwise asked about. Lines are classed Safe, Caution or Hard; Hard lines (`sudo`, `rm -rf`, `git push`, writes outside the worktree, `[exec] hard` patterns) are always a Red card (spec 061).
- `shell-auto` mode runs safe shell lines without asking; `[s]` / `/s` allows similar shell commands for the session, and `/permissions revoke` ends the grants.
- `!<line>` in the console runs a line yourself via `shell.run`; the output is never sent to a model.

### Validator

- Weak sources are labelled, never evidence (spec 040-A2): a claim only Weak sources support is `unverified (weak)`, and agreement among Weak sources is recorded but changes no label. New `[validator] weak_sources = "label"|"off"` (default `label`).
- A Wikipedia sentence tagged "citation needed" or carrying no citation, and a journal-publisher page with no DOI, no longer count as sources (spec 040-A3).

### Research

- A keyless search engine, `parallel` (Parallel's hosted MCP server; no key or account, rate limited; it sees the query text), and it is now the default when `[search] providers` is unset (spec 028-A3). Brave and the others are unchanged; `providers = []` turns research off.

Entries carry `source_class`.

New daemon methods `pending.list`, `pending.ratify`, `pending.discard` (console only).
