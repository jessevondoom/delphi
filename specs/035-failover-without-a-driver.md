# Spec 035: Failover without a driver's seat

## 1. What this is
The point of checking down to a lesser model is that **no work is lost**, not that the work continues quickly. Resilience over speed: a slower, more careful path that saves first is the right one.

Claude is the best default and stays the default. But nothing in Delphi should assume it is the only driver: when Claude runs out, the work should be able to continue on Gemini or on a local model, either to finish the task in hand or after asking the operator. `specs/002` §4.1 already built the machinery (a pool with per-endpoint state, exhaustion detection, promotion at a turn boundary, a confirmation card for a weaker substitute). This spec says where the code still leans on Claude, and what to change.

## 3. Decisions (proposed)
| # | Decision |
| :-- | :-- |
| D-1 | **No family is special in code.** The primary family is `[access] primary`; if unset it is `claude` when an allowed Claude endpoint exists, else the first allowed family in declaration order. `role_family` still overrides it per role. |
| D-2 | **The order after the primary is the operator's.** `[access] failover = ["gemini", "local"]` lists the families tried, in order, when the primary has nothing usable. Unlisted families follow in declaration order, `local` last. |
| D-3 | **Two kinds of stand-in.** A **peer** (at least the wanted tier, context not shorter, not reduced) takes over without asking, as a *similar* model does today. Anything else is **weaker**: a lower tier, a shorter context, or a **reduced** model. A model is reduced when its endpoint is `cost_model = "local"`, unless the catalog entry says `reduced = false`; any model can be marked `reduced = true`. A reduced model is never a peer of a model that is not reduced, whatever tier it is mapped to. |
| D-4 | **The operator chooses what "weaker" means for work in hand.** `[access] on_weaker = "ask" \| "finish" \| "never"`, default `ask`. `ask`: the card, as today. `finish`: a task already under way (its span has made a model turn, or a card has already covered it) carries on on the stand-in without a card, the switch is logged and shown; a task that has not started asks. `never`: no weaker model runs; the task waits for the primary. Both keys live in `[access]`, which is ratified, so changing them is a Red proposal. |
| D-5 | **The unit of consent is the task**, unchanged: an answer to a card covers that target→substitute pair for that task, survives a restart, and silence is not consent. |
| D-6 | **The primary takes back over by itself.** Every model turn asks the router again, so when the primary's quota returns the next turn uses it. History is rebuilt for the target provider (`specs/002` §3.1), signed reasoning is not carried across. |
| D-8 | **Account-level exhaustion takes the whole endpoint out.** A billing error, a monthly spend cap or an account spend limit (`Exhaustion::is_account_wide`) marks every model on that endpoint exhausted at once, so the next candidate is on another endpoint or family, never a lesser model on the account that is out. A model's own quota (a CLI "quota reached", a long `retry-after`) stays one model's. |
| D-9 | **A stand-in that is no step down is silent; a step down is saved first.** The ladder: (1) the same model on another endpoint; (2) **any model at least as capable**, the closest tier first (equal before higher), and at one tier the model's own lineage before another (Opus out: Gemini's top tier takes over without a question); (3) only when the tier must go **down**, or to a reduced (local) model, or to a shorter window: the save-point (D-11) and the card, and there too **the model's own lineage first, the most capable first** (Opus, then Sonnet, then Haiku), other lineages after, a reduced model last. Quotas are kept per `(endpoint, model)`, so a model that is out never takes its siblings with it, except for an account-level failure (D-8). |
| D-10 | **A model's lineage is not always its endpoint's family.** Gemini's subscription serves Claude and GPT-OSS models from a pool of their own. `[models.catalog."<id>"] lineage = "claude"` says a model belongs to a lineage other than its endpoint's family; the ladder's "same lineage" uses it, and the quota state stays per endpoint and model. |
| D-11 | **Save first, silently, before anyone is asked.** When the only way on is a weaker model, the weaker model first writes a **save-point** for the task: (a) where the work stood when the model ran out, (b) a summary of the chat session, (c) the pointers a resumption needs (task, span, event range, worktree and branch, pending approvals). It goes to `local/missions/<id>/checkpoints/NNN-<task>.md` and is logged as `checkpoint.saved`. The record of what happened (a) is built from the log and the span's history **without a model**, so it exists even if the weaker model fails; the model-written summaries are added when the weaker model answers within a time limit, and are left out for a session that read untrusted content. It happens once per task and substitute, survives a restart, and takes as long as it takes. |
| D-12 | **Then the operator is told, in this order:** which model ran out, that the work is saved and where, and whether to accept the weaker model and continue. Declining, or no answer, leaves the save-point and waits for the primary; the task can be resumed later from it. |
| D-13 | **What each policy does after the save-point.** `ask`: the card. `finish`: carries on if the task is under way. `never`: waits. **An optimistic build (`/build --optimistic`; Amendment 035-A1: not a permission mode) continues without a card, carefully:** the save-point is still written, the switch is logged and shown, and while the task runs on the weaker model the permission mode's automatic approvals (worktree edits, pinned installs) are **off for that task**, so each write asks; Red actions are never automatic in any mode. |
| D-14 | **No role starts on the top tier.** Every shipped role has a `default_tier` in its `AGENT.md`: `workhorse` (Sonnet-class) for the orchestrator, architect, builder, red-team, strategist and writer, `fast` for the scout, messenger and investigator. Without one, no profile gives `frontier`. The lint refuses `default_tier: frontier` in a built-in manifest; an operator's own `custom/` override may. |
| D-15 | **The Orchestrator raises a role for a task; it never lowers one to save cost.** `dispatch_agent` takes `tier` (`fast`, `workhorse`, `frontier`) and `tier_reason`. Raising above the role's default without a reason is refused, with what to give; asking for less than the default is refused too: a model is stepped down only when the one it needs is unavailable (failover, with its save-point), never for efficiency, which is what the default is for. The request is recorded on the span's start (`dag.node.added`: `tier`, `default_tier`, `tier_reason`) and shown in the narrator. Cost is bounded as always by the budget reservation. |
| D-15a | **Amended 2026-10-29 by spec 056 (operator-ratified OD-1).** A role has a **floor** and a **preferred** class instead of a default tier, and in `[routing] assignment = "discovered"` any pool model meeting the floor is eligible, ranked by measured results, then quota; a task that carries a plan and a deterministic gate may start below preferred by the ratchet, never below the floor. D-14 and D-15 stand unchanged under `assignment = "static"`, which stays the default. The Orchestrator's own discretion to lower a model remains withdrawn. |
| D-16 | **The panes show the model that really served the call.** The tier on an event is the tier of the model that served it (`route::served_tier`), not the tier asked for, so a stand-in shows as what it is. The agents pane marks a model **▲ above** or **▼ below** its role's default (with the reason if the orchestrator chose it), the dashboard's running rows carry the model with the same mark, and a sub-agent row shows its own model. |
| D-17 | **The operator can change the defaults by asking, and is told what changed.** The shipped defaults are tuned in the core (`agents/*/AGENT.md`); the operator's word over them lives in the workspace, in `local/settings.toml` (never in the release), and is read afresh when a span starts. Settable by a prompt: `role_tier.<role>` (`fast`, `workhorse`, `frontier`, or `default` to go back) and `mission_budget_usd`. The orchestrator has a `change_setting` tool (`settings` in its manifest's `execute` list); the reply is exact ("architect now starts on frontier (it started on workhorse; shipped: workhorse). Undo: /settings reset architect."), is logged as `setting.changed`, and appears in the chat as the daemon wrote it, so it is said once whatever the model adds. The operator's own commands are `/settings set`, `/settings reset` and `/settings` (what each role starts on). Permissions, endpoints, access, hooks, exec and the relay are not settable by a prompt; the refusal names the command that is. |
| D-18 | **A prompt may change a setting only if the operator really wrote it.** The tool is applied only when the task is a console message from the operator (`task.created` carries `source: operator`), it is the root span, nothing untrusted has been read in it (taint ceiling L5), and `quote` (the operator's own words, at least eight characters, copied from the message) is found in that message. Otherwise nothing changes and the request becomes a **suggestion**, and the reply says why. So a page, a file or a dispatched agent cannot change a setting, and neither can the model on a guess. |
| D-19 | **Delphi learns from use and suggests; the operator answers.** A suggestion (`setting.suggested`: `usage`, `model` or `prompt`) waits in the log until `/settings accept <n>` (applies it, logged with the suggestion's id) or `/settings dismiss <n>`; a change to the same key supersedes it. The first source is use: when the orchestrator has raised one role to one tier for three tasks in a mission, Delphi suggests making it the role's default, once. The learning layer (`specs/031`) can feed the same list. |
| D-20 | **A Council is raised on demand and lowered only by failover.** `/council --tier frontier` raises every seat; asking for less than a seat's default is refused. A seat whose model is unavailable steps down like any task (save-point, card or policy). |
| D-7 | **It is visible.** The narrator's state carries which models are out (and until when) and which roles are running on a stand-in (from which model, why, whether the operator agreed or the policy did); the dashboard shows it. |
| D-21 | **A pace spreads work over the providers for now; it never lowers a model.** `/pace sprint\|frugal\|balanced` (or asking, as for any setting) sets a pace the daemon keeps in memory: it lasts until set back or the daemon stops. It changes only the order among the pairs at the wanted tier, after the avoided families and before the role's own family: **sprint** (fastest progress) puts a provider that is being throttled or cooling down last, so work goes where it will run now; **frugal** (token efficiency) puts subscription and local providers first, so the metered ones are kept for when they are needed. No role starts on a lower tier because of it (D-15 stands), a stand-in is still found by the ladder (D-9), and a lower or reduced model still needs the card. The reply is exact and logged as `setting.changed` (`pace`); `observe.state` carries `pace_mode` and a `providers` list (per endpoint: models, cooling, out, when the soonest returns), which the dashboard draws as rings and bars, and the sprint / frugal switch with more than one provider. Assumed, not measured: whether either order actually speeds up or saves anything on a live mission. |

## 4. How it fits together
```
request ─► ideal = first usable of: target model, else primary family at the wanted tier
            │ usable            ─► Target
            └ not usable ─► the ladder (D-9), each model on its own quota:
                  1. the same model on another endpoint                          ─┐
                  2. any model at least as capable: closest tier, own lineage     ├─ Similar (silent)
                     first at a tier (Opus out: Gemini's top tier)                ─┘
                  3. a step down, same lineage first (Opus → Sonnet → Haiku)      ─┐
                  4. a step down elsewhere; a reduced (local) model last           ├─ Weaker
                  nothing ─► park (blocked: no_model)                              ─┘
            Weaker ─► SAVE-POINT first, silently, by the weaker model (D-11)
                        ├ ask      ─► the card: what ran out, where the work is saved, accept?
                        ├ finish   ─► carries on if the task is under way, else the card
                        ├ never    ─► waits for the primary (the save-point stays)
                        └ optimistic ─► carries on, carefully: this task's writes ask (D-13)
```
A reduced model that is the *only* configured one is just the ideal and runs normally. A reduced model is never called "similar". A billing error or spend cap takes every model of the endpoint out (D-8); a model's own quota takes only that model out.

## 6. Acceptance criteria
- **AC-1:** with Opus unavailable and only a local model left, the route is *weaker* with `a reduced local model` among what is lost, never *similar*, even though the local model is mapped to the frontier tier.
- **AC-2:** a workspace with only Gemini endpoints prefers Gemini for every role; `[access] primary` and `role_family` override.
- **AC-3:** `[access] failover = ["local", "gemini"]` makes the local model the first stand-in; the default puts `local` last.
- **AC-4:** `on_weaker = "ask"` raises the card; `"finish"` runs a task in flight without one and a task not yet started with one; `"never"` runs nothing weaker and parks the task.
- **AC-5:** a peer on another family still takes over without a card.
- **AC-6:** `observe.state` lists the models that are out with their reset times and the roles running on stand-ins; the dashboard shows both.
- **AC-7:** the keys are in the ratified `[access]` block (a local edit is a pending proposal until ratified).
- **AC-8:** a billing error on an endpoint makes none of its models a candidate, and no card offers one.
- **AC-9:** with Opus out and a Gemini top-tier model up, the Gemini model takes over with no card; with the equal-tier models gone, the route is Sonnet (same lineage, a step down) with the card, then Haiku, then a lesser model of another lineage; at one tier the model's own lineage wins (Sonnet on Bedrock before Gemini Flash).
- **AC-10:** a Claude model served through the Gemini subscription (`lineage = "claude"`) counts as the same lineage.
- **AC-11:** before any card, a save-point file exists with the task, the reason, the last turns, the session and the resume pointers; `checkpoint.saved` precedes `approval.requested`; the card names the file.
- **AC-12:** if the weaker model fails to write its summaries the save-point still exists, with the part built from the log; for a tainted task no model-written text is in it.
- **AC-14:** no shipped manifest starts on `frontier`; the lint refuses it for a built-in role.
- **AC-15:** `dispatch_agent` with a higher `tier` and no `tier_reason` is refused; with one, the child runs on the model of that tier and its span start records the request.
- **AC-16:** after a failover the usage events carry the tier of the model that served them; the agents pane marks the model above or below the role's default.
- **AC-17:** a prompt that quotes the operator's words changes a role's default or the budget, the reply states exactly what changed, and the chat shows it once; the next task starts on the new tier.
- **AC-18:** with no quote, a quote not in the message, untrusted content read in the task, or a dispatched span, nothing changes and a suggestion is recorded; `permissions`, access keys and the like are refused with the list of what can be set.
- **AC-19:** three raises of one role to one tier make one suggestion; accepting it applies it, dismissing it is final.
- **AC-20:** `dispatch_agent` and a Council refuse a tier below the default; a Council raised with `--tier` seats everyone at that tier.
- **AC-21:** with a provider being throttled, `sprint` serves a request from another provider at the same tier and `frugal` from a subscription or local one first; neither moves a request to a lower tier or raises a card, `balanced` is the usual order, and the pace is gone when the daemon restarts.
- **AC-13:** with `never` the save-point is still written; in an optimistic build no card is raised, the task continues, and its writes ask until it finishes.

## 7. Open
- A capability score per model (a number, not a class) so that "weaker" can be judged between two cloud models of different quality; today tier and context are all there is.
- Whether a Council seat may be a reduced model (it would be a weak voice in a debate).
- `finish` for a task that has a pending write: stop at the next approval card instead of finishing on a weaker model.

## 8. Amendment 035-A1: D-4 and D-13 follow the per-build flag (council 013 D3 b)
The "optimistic mode" of D-13 (and the F7 and AC-13 wording) is the per-task optimistic flag of a `/build --optimistic` task, not a permission mode; `optimistic` is no longer a `/permissions` value (`specs/015` 015-A1). D-4's `finish` is unchanged. The weaker-model save-point, the logged switch and "this task's writes ask" behave as before.
