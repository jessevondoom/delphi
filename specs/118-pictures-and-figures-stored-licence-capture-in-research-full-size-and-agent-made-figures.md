# Spec 118: Pictures and figures

> **Status: approved by the operator, 2026-11-14** (see the frontmatter). Seventh of eight specs (112 to 119) from the knowledge-loop audit.

## 1. Scope and objectives

| # | Observation (code on `main`, 2026-11-14) |
| :-- | :-- |
| E-1 | The console's research job captures pictures with a licence decision made by code for each picture: Creative Commons BY, BY-SA, CC0 and public domain are accepted; non-commercial, no-derivatives, GFDL, fair use and anything unrecognised are refused. Licence, author and credit address are stored and an attribution line is written under the picture. |
| E-2 | The host research runner captures no picture. |
| E-3 | When a page is expanded, pictures pass the same licence decision, and then only the bytes are written: the licence, author and credit address are thrown away (`library.rs`, the asset capture). 097 §4.5.2 asks for them to be kept with the asset. |
| E-4 | The image method returns pictures shrunk to at most 160 pixels a side. The app cannot ask for a library picture at all. The terminal draws pictures as blocks of colour. |
| E-5 | SVG and WebP pictures are dropped, which excludes most diagrams on the open web. |
| E-6 | Agents can write charts and diagrams as mission artifacts (095). A generated page accepts library pictures only, so none of those can appear in one. Mermaid text in a document is not drawn in the app. |
| E-7 | On the audited workspace no picture has been captured. |

Objective: a topic page shows pictures at a readable size, each with its licence and credit, drawn from research wherever the licence allows, and figures an agent made from the page's own records.

### 1.1 Non-goals

- No picture is kept or shown on any basis other than the licences accepted today, or the operator's own trusted-list entry that says a host's pictures may be kept.
- No picture generated by an image model.
- No picture is ever sent outside the machine by this spec; export is 117 §5.4.

### 1.2 Simpler alternative considered

*Link to pictures on the web instead of keeping them.* Rejected: the app loads nothing from the network (111 §2), a link breaks when the page changes, and a hot link shows the picture without the stored credit. Keeping the file with its licence record is what makes attribution checkable.

## 2. A licence record for every asset

1. Every picture kept anywhere (research entries, library assets) has a record beside it: `source_id`, the picture's own address, `licence` (a fixed identifier), `licence_evidence` (which of the three checks decided it, and the address of the evidence), `author`, `credit_url`, `share_alike`, `retrieved`, the file's hash, width and height.
2. A picture with no record is not served to a page, the console or the app. The image method answers `no licence record`.
3. `delphi library assets check` lists assets without a record and, with `--apply`, moves them to `assets/unlicensed/`, which is never served. It deletes nothing.
4. A page that shows a picture shows under it, written by the daemon and not by the writer: author, licence name, and the credit address. The page check fails a page whose figure lacks the line.
5. A share-alike picture carries the notice to the exported page (117 §5.4).

## 3. Capture in research

1. The one runner of [`specs/112`](112-one-research-record-a-single-runner-topics-that-persist-and-claims-that-reach-the-library.md) captures pictures by the gates of today (trusted host, alternative text, at least 48 pixels a side, size cap, per-source and per-run limits), on by default for trusted hosts and switchable with `[research] images`.
2. Captured pictures are library assets tied to their source, so a page citing the source can show them.
3. `record_research` ([`specs/113`](113-host-led-research-ingest-a-record-tool-and-workers-that-can-capture.md)) may name picture addresses on a public source; the daemon applies the same gates and decision. A host cannot hand over picture bytes.
4. Refusals are recorded in the research record with the reason, so the operator can see what was left out and why.

## 4. Formats and size

1. WebP is accepted and stored as it is.
2. SVG is accepted from trusted hosts only and is never shown as SVG. At capture the daemon renders it to a PNG with a renderer that runs no script, loads no external resource and ignores embedded links; the SVG file is kept beside the PNG for the record and is never served. A file over 2 MiB or one the renderer rejects is refused.
3. The image method takes `max` (pixels a side, up to 1,600; default 160 as today). The stored file is never enlarged.
4. The app may request library pictures that have a licence record; its bridge list gains that form of the image read and nothing else.

## 5. Figures agents make

1. A figure is a chart or diagram produced by the tools of 095 from records a page cites. The writer may ask for one in a page by naming a figure spec: the kind, the data rows or the nodes and edges, and the claim or source markers the data came from.
2. The daemon renders the figure with the existing chart and diagram code, stores it as an asset with `licence: "generated"`, `made_by: <role>`, and the markers it rests on, and writes under it: `Figure made by <role> from [markers]. Not from a source.`
3. The page check verifies that every number in a chart's data appears in a cited claim or passage, and every node label of a diagram appears in the page text. A figure that fails is dropped from the page and the failure recorded.
4. Mermaid blocks in stored documents are drawn in the app by a bundled, pinned renderer with no network access, in strict mode, with the text shown on failure.
5. Figures made as mission artifacts stay where they are; "add to a topic" for an existing artifact is left to a later slice.

## 6. Acceptance criteria

1. **AC-1:** a picture captured when a page is expanded has a record with licence, author and credit address; the page shows the line under it.
2. **AC-2:** an asset with no record is refused by the image method, and `assets check` lists it.
3. **AC-3:** a host research run on a fixture page with one openly licensed and one unlicensed picture keeps the first, refuses the second, and records why.
4. **AC-4:** an SVG fixture containing a script and an external image reference renders to a PNG with neither executed nor fetched (the test transport sees no request).
5. **AC-5:** the image method with `max: 1200` returns a picture 1,200 pixels on its longer side when the original is larger, and the original size when it is smaller.
6. **AC-6:** a chart whose data holds a number found in no cited record is dropped by the check.
7. **AC-7:** the app shows a library picture with its credit line; a request for an asset without a record shows the refusal, not a broken picture.

## 7. Verification plan

## 9. Authority and trust

- The licence decision stays in code and stays as strict as today. No model decides a licence.
- SVG is the one new parser of untrusted input; it runs at capture, inside the daemon's existing limits, with no script and no network.
- A figure is labelled as made by an agent and is checked against the records; it is never presented as coming from a source.
