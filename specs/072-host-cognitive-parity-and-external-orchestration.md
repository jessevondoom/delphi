# Spec 072: Host cognitive parity and external orchestration

## 1. Scope & Objectives

An operator works inside Delphi's TUI and also across external host harnesses (Claude Code, Antigravity/`agy`, Copilot CLI, Cursor). This specification establishes **functional and cognitive parity** for agents operating in external harnesses via Delphi's Model Context Protocol (MCP) server:

1. **Identity & Provenance:** External agents identify with Delphi's canonical badges and attribution: `⟦badge⟧ Name (role) via delphi`, making clear to the operator that Delphi's epistemic discipline is active (§3).
2. **Orchestrator as External Guide:** The `orchestrator` acts as an interactive technical advisor to host models, triaging tasks against the complexity escalation ladder, recommending optimal specialist rosters, supplying execution contracts, and dynamically compiling specialized agent packs (§4).
3. **Internal Knowledge as a First-Class RAG Source:** Delphi's internal knowledge base, library claims, and context documents are exposed through structured semantic/hybrid retrieval with explicit epistemic status markers and citation locators (§5).
4. **Full Scoped Memory Access:** Role-specific memory, heuristics, lessons, and project learnings are fully queryable via MCP, replacing truncated summaries with structured facet exploration while strictly enforcing project and home tenant isolation (§6).
5. **Suggested, Non-Mutating Scaffolding:** Unregistered or empty directories are detected by the `orchestrator`, which proactively suggests Delphi project scaffolding (`.delphi-project`, `_index.md`, `specs/`, `plans/`, `context/`, `research/`, `work/`) without performing automatic or silent file writes (§7).
6. **Dual-Mode Councils:** Councils may be executed either daemon-internally (heavyweight, with daemon in-memory barriers under 003/062) or host-federated (agile, executed by host subagents following the `orchestrator`'s structured 3-round sparse deliberation agenda) (§8).

### 1.1 Non-Goals

- **Widening Authority:** A Delphi role running in an external host possesses **instructions, not authority** (062 §4.4). The host harness remains bound by its own OS and user-approval permissions. Delphi agents outside the Delphi harness do not inherit Delphi's merge gates, sandbox worktrees, or autonomous spend authority.
- **Silent Project Scaffolding:** No MCP call may create directories, write files, or register project markers without explicit operator intent. Clean directories trigger advice, not mutation.
- **Cross-Project Memory Bleed:** Host agents in Project A cannot read private lessons or memory from Project B.

### 1.2 Simpler Alternative Considered

*Rely solely on static `get_agent` prompts and single-line search (`search_kb`).* Rejected by Council: static prompts force the host model to solve all orchestration dilemmas alone, cause `FM-1.2` (role creep) and `FM-2.5` (sycophantic consensus), provide zero RAG chunking, and leave empty folders devoid of Delphi's spec-first structure.

## 2. Principles

1. **Parity of Mind, Asymmetry of Execution:** An agent outside Delphi thinks with the same cognitive profile, heuristics, and counterweights as inside Delphi, but executes strictly under the host's permission model.
2. **Deterministic Role Specialization:** Dynamic agent definitions generated by the `orchestrator` are compiled from immutable canonical prototypes (`AGENT.md` + Governance Preamble) using deterministic templates. The `orchestrator` may not hallucinate arbitrary role permissions or omit disclaimers.
3. **Fail-Closed Isolation:** Memory and RAG queries resolve strictly against the active project ID and home layer. Ambiguous project contexts fail closed.
4. **Suggested, Never Automatic Scaffolding:** Scaffolding advice is a navigational affordance, never an unprompted disk mutation.
5. **Dissent-Preserving Councils:** Whether convened inside the daemon or federated across host subagents, a Council ruling is invalid without an explicit, verbatim Minority Report.

## 3. Identity and Attribution Surface

Amends [`specs/066`](066-mcp-research-endpoint-and-role-identity.md) §7.

### 3.1 The Canonical Attribution String

The `Identity::signature` function in `crates/delphi-core/src/research.rs` is amended so that any Delphi role served over MCP outputs:

```text
⟦badge⟧ DisplayName (role) via delphi
```

Examples (using generic role descriptors, display names rendered from theme at run time):
- `⟦•─•⟧ Name (orchestrator) via delphi`
- `⟦•_•⟧ Name (architect) via delphi`
- `⟦-_-⟧ Name (red-team) via delphi`
- `⟦•─•⟧ Name (builder) via delphi`
- `⟦•_•⟧ Name (strategist) via delphi`

### 3.2 The Authority Disclaimer

Because external agents run in harnesses without Delphi's daemon sandbox or 5 merge gates, every agent pack header and MCP instruction string must carry the immutable disclaimer:

> *"[Advisory only — Host sandboxing, shell permissions, and approval gates apply. Instructions do not confer system authority.]"*

## 4. Orchestrator Guidance & Dynamic Role Spawner

### 4.1 Tool: `consult_orchestrator`

The external host model consults the `orchestrator` to determine workflow strategy:

```json
{
  "name": "consult_orchestrator",
  "description": "Consult the Lead Orchestrator on task decomposition, specialist roster selection, and execution strategy.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "task": {"type": "string", "minLength": 1, "maxLength": 2000, "description": "The user's objective or coding problem."},
      "ambiguity": {"type": "string", "enum": ["low", "medium", "high"], "default": "medium"},
      "blast_radius": {"type": "string", "enum": ["isolated", "module", "system-wide"], "default": "module"},
      "proposed_approach": {"type": "string", "maxLength": 1000}
    },
    "required": ["task"],
    "additionalProperties": false
  }
}
```

**Output Structure:**
- `recommended_escalation`: Level 1 (Direct Hunt), Level 2 (Scoped Pipeline), Level 3 (Spec-First DAG), or Level 4 (Council Mode).
- `suggested_roster`: Ordered array of roles with concrete rationale (e.g., `["architect", "red-team", "builder"]`).
- `execution_contract`:
  - `constraints`: Specific rules and anti-patterns to enforce.
  - `context_pointers`: Files or specs the host should read first.
  - `definition_of_done`: Deterministic predicates required before declaring completion.

### 4.2 Tool: `spawn_agent_pack`

For specialized domain tasks requiring personas beyond the default 13 roles, the `orchestrator` compiles an ephemeral agent pack:

```json
{
  "name": "spawn_agent_pack",
  "description": "Compile a specialized agent pack derived from a canonical Delphi archetype.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "base_role": {"type": "string", "enum": ["architect", "builder", "investigator", "scout", "red-team", "strategist", "writer", "validator", "administrator", "assistant", "advocate"]},
      "specialization": {"type": "string", "minLength": 1, "maxLength": 64, "description": "E.g., 'database-migrator', 'cryptographer', 'api-refactorer'."},
      "domain_focus": {"type": "string", "maxLength": 200},
      "custom_heuristics": {"type": "array", "maxItems": 5, "items": {"type": "string", "maxLength": 200}}
    },
    "required": ["base_role", "specialization"],
    "additionalProperties": false
  }
}
```

**Deterministic Template Composition Invariant:**
An ephemeral pack is generated deterministically by concatenating:
1. Universal Delphi Governance Preamble (non-negotiable constraints, authority boundary).
2. Canonical `AGENT.md` of `base_role` (preserves cognitive profile and counterweights).
3. Active Project Scope Context (specs, plans, index).
4. Specialized domain heuristics and focus area.

## 5. Knowledge Retrieval as a RAG Source

Extends [`specs/064`](064-knowledge-retrieval-for-agents-and-mcp.md).

### 5.1 Tool: `kb_retrieve`

Exposes high-precision semantic/hybrid chunk retrieval for host models to use as Retrieval-Augmented Generation (RAG):

```json
{
  "name": "kb_retrieve",
  "description": "Retrieve chunked passages, sourced claims, and verified specifications from Delphi's knowledge base and project context.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": {"type": "string", "minLength": 1, "maxLength": 500},
      "limit": {"type": "integer", "minimum": 1, "maximum": 10, "default": 5},

      "scope": {"type": "string", "enum": ["all", "project_only", "core_only"], "default": "all"}
    },
    "required": ["query"],
    "additionalProperties": false
  }
}
```

### 5.2 Chunk Format & Epistemic Annotations

Every passage returned by `kb_retrieve` is wrapped in structured metadata:


Status mapping conforms to [`specs/052`](052-knowledge-status-capture-on-contact-and-the-digest.md): `noted`, `checking`, `validated`, or `contested`.

## 6. Full Scoped Memory Access

Extends [`specs/062`](062-delphi-as-host-agent-mcp-server.md) §5 and [`specs/064`](064-knowledge-retrieval-for-agents-and-mcp.md) §6.

### 6.1 Tool: `query_memory`

Allows host agents to query the complete memory graph across roles, heuristics, and project learning:

```json
{
  "name": "query_memory",
  "description": "Explore the full graph of Delphi agent memories, lessons, heuristics, and decisions.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "role": {"type": "string", "maxLength": 64, "description": "Filter by role ID, or omit for shared team memories."},
      "facet": {"type": "string", "enum": ["all", "lessons", "heuristics", "decisions", "reflections"], "default": "all"},
      "query": {"type": "string", "minLength": 1, "maxLength": 500},
      "limit": {"type": "integer", "minimum": 1, "maximum": 20, "default": 10}
    },
    "required": ["query"],
    "additionalProperties": false
  }
}
```

### 6.2 Tenant and Scope Isolation Rules

1. **Active Project Constraint:** Results are strictly bounded to the active project layer (resolved via working directory) plus the shared home layer (`$DELPHI_HOME/operator/`).
2. **Cross-Project Fail-Closed:** Any query attempting to specify a project ID differing from the resolved working directory is refused with `error: forbidden_cross_project_query`.
3. **Private File Exclusions:** Credentials, event logs, and unratified L0 proposals from other sessions are strictly excluded.

## 7. Suggested Project Scaffolding

Extends [`specs/058`](058-project-scopes-scaffolding-and-promotion.md) §5.

### 7.1 Tool: `scaffold_status`

Inspects whether the current working directory is an initialized Delphi project:

```json
{
  "name": "scaffold_status",
  "description": "Check if the current workspace is a registered Delphi project, and inspect available scaffolding.",
  "inputSchema": {"type": "object", "properties": {}, "additionalProperties": false}
}
```

**Response Format:**
```json
{
  "initialized": false,
  "registered": false,
  "working_directory": "/path/to/project",
  "scaffold_recommended": true,
  "suggested_command": "delphi project init",
  "preview_paths": [
    ".delphi-project",
    "_index.md",
    "specs/",
    "plans/",
    "context/",
    "research/",
    "work/"
  ],
  "guidance": "This directory is not an initialized Delphi project. You can recommend the operator run 'delphi project init' to create the standard spec-first folder structure, or continue working in ad-hoc mode."
}
```

### 7.2 Invariant: Zero Automatic Writes

Neither `delphi mcp` nor any tool exposed over MCP may automatically scaffold an empty folder. Scaffolding must always be suggested to the user or triggered by an explicit operator CLI command.

## 8. Dual-Mode Councils: Internal vs. Host-Federated

Amends [`specs/003`](003-collaboration-and-council.md) §4 and [`specs/062`](062-delphi-as-host-agent-mcp-server.md) §7.

### 8.1 Mode A: Daemon-Internal Council (`request_council`)
The existing MCP tool `request_council` dispatches to Delphi's daemon state machine. The daemon enforces in-memory blind barriers, routes heterogeneous model families, and writes the verdict to `missions/`. Ideal for high-stakes, security-critical architectural decisions.

### 8.2 Mode B: Host-Federated Council (Host-Orchestrated)
When the operator works in an external harness without a running daemon or wishes to deliberate entirely within the host's subagent runtime, the `orchestrator` provides the **Council Agenda Kit** via MCP prompt:

- **Prompt: `council/federated_agenda`:**
  Instructs the host model to run the 3-round sparse deliberation protocol:
  1. **Round 1 (Blind Parallel Opening):** Dispatch 3–4 subagents independently without shared history (`architect`, `red-team`, `strategist`).
  2. **Round 2 (Asymmetric Cross-Examination):**
     - `red-team` attacks failure modes (`P0/P1`).
     - `strategist` audits timeline, ROI, and scope creep.
     - `architect` synthesizes structural solutions.
  3. **Round 3 (Verdict & Minority Report):**
     - Required output syntax:
       ```text
       DECISION: <one-sentence ruling>
       NEXT <role>: <concrete next step>
       ## Accepted Risks & Minority Report (Red-Team / Dissent)
       <verbatim unresolved P0/P1 critique, or "Unanimous — no unresolved P0/P1">
       ```

### 8.3 Ingestion: `propose_council_record`

Host models submit the transcript of a federated Council back into Delphi:

```json
{
  "name": "propose_council_record",
  "description": "Stage the results of a host-federated Council into Delphi's mission log.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "question": {"type": "string", "minLength": 1, "maxLength": 1000},
      "decision": {"type": "string", "minLength": 1, "maxLength": 500},
      "seats_consulted": {"type": "array", "items": {"type": "string"}},
      "minority_report": {"type": "string", "minLength": 1, "maxLength": 4000},
      "full_transcript": {"type": "string", "maxLength": 30000}
    },
    "required": ["question", "decision", "minority_report"],
    "additionalProperties": false
  }
}
```

The record is staged in `missions/` under tier L0 and presented to the operator at the next `/retro`.
