# Decisions pane: design options

Generated by Gemini 3.8 Flash High via agy; unreviewed first pass.

## Option 1: Option 1: Linear Triage Feed (Document Stream)

A calm, single-column reading feed that presents each pending decision as a spacious indented card directly in the scroll stream. Operators scan vertically, toggle batch-eligible recommendations with Space, or press Enter to expand into a full conversational detail card.

**Tradeoffs:** Strengths: Uncompromised readability and ample room for the full 2-3 sentence summaries and rationale without truncation; perfectly embodies Delphi's borderless, quiet aesthetic. Weaknesses: Requires vertical scrolling when backlog exceeds 3-4 items; cannot preview details side-by-side with the queue.

## Option 2: Option 2: Split-Deck Master-Detail (Inspector Desk)

A persistent two-column console dividing the deck into a 35-column master queue on the left and a 62-column live inspector on the right. Moving up and down the queue instantly previews the selected decision's full summary and impact without navigating away, while pressing Enter focuses the inspector and activates the prompt bar.

**Tradeoffs:** Strengths: Zero screen-jumping when triaging multiple decisions; instantaneous situational awareness of both the queue size and active item details; excellent for fast keyboard scrubbing. Weaknesses: 58-character line limit in the right pane requires tighter prose wrapping; requires an adaptive layout collapse at 80x24 because two columns cannot comfortably coexist below 90 columns.

## Option 3: Option 3: Grouped Priority Matrix (Tier-Rail Console)

A safety-partitioned triage console that segregates decisions into three rigid horizontal risk tiers: Tier Red Interventions (strictly manual 1-by-1, no checkboxes), Tier Amber Optimistic Ratifications (batch-eligible with second seat), and Open Spec Questions. Each tier features dedicated batch accelerators and visual barriers so routine approvals can never be conflated with security-boundary approvals.

**Tradeoffs:** Strengths: Maximum psychological safety against accidental authorization leaks; enforces Delphi's charter rule that Red actions never have batch defaults by isolating them physically; perfect cognitive grouping for high-velocity swarm pipelines. Weaknesses: Consumes extra vertical real estate with section banners; if all pending decisions happen to fall in one tier, the other tier headers feel redundant.

## Recommendation

I recommend Option 1 (Linear Triage Feed) as Delphi's primary canonical interaction design, synthesized with two key ideas from the other options: (1) Borrow Option 3's strict visual isolation and hotkeys for Tier Red items so that red actions without safe defaults can never visually blend into batchable items or render checkboxes; and (2) Adopt Option 2's Master-Drawer responsive adaptation for the 80x24 viewport, which keeps both the scroll list and active item preview readable on compact displays without aggressive truncation. Option 1 honors Delphi's core aesthetic—spacious typography, zero window borders, calm document-like scanning, and clear human authority over swarm execution.

## Open questions

- Batch Ratification Scope across Tiers: Should Tier Red spec approvals (e.g. specs/028-bundle-streaming.md with an architect recommendation) ever be batch-eligible if the operator has reviewed them, or should batching strictly be reserved for Amber optimistic builds and non-breaking open questions?
- Interactive Prompt Bar Memory / Context: In the Detail view, when the operator types a query in the prompt bar (e.g. 'why does staging require schema update?'), should the agent's answer appear inline in the decisions pane replacing the alternatives, or should it automatically switch deck focus to the Center Deck (chat) with the decision context pinned?
- Provisional Rollback Mechanics: For optimistic builds (DEC-082), if the operator rejects a provisional decision in the detail view, should Delphi automatically create and execute a git revert commit, or should it pause the worktree and ask for explicit revert instructions?
- Timeout Expiration Behavior: The header shows an active countdown ('09:14 remaining'). When the countdown reaches '00:00', does Delphi pause all dependent swarm tasks indefinitely, or does it fall back to a safe default (e.g. deny Red actions, revert unratified optimistic builds)?
- Keyboard Navigation Accelerators: Would you prefer dedicated hotkeys for immediate triage without entering detail views (e.g. 'y' to accept highlighted recommendation directly from the main list, 'n' to reject), or must every single decision require opening the detail view unless explicitly batch-checked?
