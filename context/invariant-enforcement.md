# Invariant → Enforcement Map

GOVERNANCE §5.6: an invariant counts as enforced only when code enforces it. Each row names where the enforcement happens:
- **Daemon:** `delphi-core` state-machine or runtime check. Agents cannot edit or bypass it (D-02).
- **CI / doctor:** a deterministic check on files.
- **Prompt-only:** an instruction to the agent with nothing mechanical behind it. Treat these as advisory.

A row moves from ❌ to ✅ when its check ships with the test named in the spec. ◐ means partly built, with the remainder scheduled for the step shown.

## Spec 098 (host-first) authority invariants

Each row maps one numbered invariant of [`specs/098`](../specs/098-where-agents-run-host-first-locus-and-the-inside-exceptions.md) §12 to the tests that enforce it, and says how far that goes. The statuses are **enforced** (a test fails if the invariant breaks), **partly** (some of it is tested; the note says what is not) and **not yet** (nothing tests it). The note is the honest part: it is written from the tests, not from the spec. A test in the *Enforcing tests* column is written `path::test_name` from the repository root, and `crates/delphi/tests/invariant_map.rs` fails if a §12 item has no row here or a named test no longer exists. A test that exists is not proof that it checks what the row says; read the test.

**Required summary (spec 098 §6, §13 S9).** After a Council, Panel or red-team review ends, the host is expected to call `record_session_summary`. The finished `council_status` or `council_result` carries a `summary` block (`expected`, `recorded`, a note). `recorded` is read from the daemon's own log (a host summary staged after the review ended), never from a host field, and `delphi doctor` counts finished reviews with none. This is best effort by design: a host cannot be made to write a summary, so the daemon tracks and says so and never holds the result back. Tested by `crates/delphi-engine/src/host_rpc.rs::a_finished_review_says_a_summary_is_expected_and_whether_the_daemon_has_seen_one_since`.
