**source excerpt, untrusted** · `specs/005-console-and-narrator-tui.md` lines 18-22

```text
This specification defines the dual-window terminal interface and local client-daemon architecture of Delphi (implemented in **Rust** using `Tokio`, `Ratatui`, and `Crossterm`):
1. **`delphi-core` Local Daemon & Unix Domain Socket (UDS) Bus:** Event-sourced runtime engine with 60Hz frame coalescing, append-only `events.jsonl` replay, and SQLite WAL state indexing.
2. **Window 1 — `Console` (`delphi` / `delphi chat`):** The sovereign operator interface, prompt input, slash-command palette, and synchronous Human-in-the-Loop (HITL) permission modals.
3. **Window 2 — `Narrator` (`delphi narrator`):** Attach-anywhere secondary live narrative and telemetry window—the epic storyteller chronicling the team's actions in real time (agents pane with models and token spend, the Epic task graph, the Council chamber, and Builder's Forge diffs).
4. **Multiplexer & OS Window Auto-Spawning:** Seamless dual-window launching across `tmux`, `zellij`, `WezTerm`, `Kitty`, and macOS windows, plus single-screen `Tab` toggle fallback.
```

## 044-decisions-pane

**044: The Decisions Pane: Every Outstanding Decision, One by One, With a Brief, a Recommendation and a Cache** · approved (per source at `b7998356ad9e`) · tier 0 · [source](../../specs/044-decisions-pane.md)

**source excerpt, untrusted** · `specs/044-decisions-pane.md` lines 20-25

```text
Decisions reach the operator in several shapes today: an approval card in the inbox, a provisional decision from an optimistic build (`/decisions`), a spec waiting for ratification, a question an agent has left open in a spec, a deadlocked council. The operator wants **one place that lists all of them, one at a time**, each with:
- a **brief**: two or three sentences saying what it is, and what it adds or changes;
- a **recommendation** where one can honestly be made (and the plain words "no recommendation: your call" where not);
- a **tick box to accept the default**, for the decisions where a default is safe, so several can be accepted together;
- a **detail view** with the same brief and recommendation, an accept button, the other choices, and the **normal prompt** so the operator can answer in their own words, with nuance;
- **no model spend after the first time**: a decision's brief and any conversation about it are produced once and stored (§7).
```
