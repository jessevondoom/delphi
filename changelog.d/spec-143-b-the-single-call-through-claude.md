- **A single model call can run through the `claude` CLI** (spec 143, slice B): when routing gives a single call to a `claude` harness, the daemon runs the CLI once, for one prompt and one answer, with its tools off. Each call gets a home built empty for it (never your own configuration home, and never a place with a `CLAUDE.md`, `AGENTS.md` or `.claude` anywhere above it), an environment of a few plain variables and the subscription token named in `[bridge.claude] credential`, and no `ANTHROPIC_API_KEY`; the prompt goes to standard input. A tool request ends the call, the answer is redacted before anything reads it, and the home is removed afterwards. Each call spends your own subscription quota, so it is limited: new keys `[bridge.limits]` (at most 30 calls or 300,000 tokens in any five hours and 100 calls or 1,000,000 tokens a day for each credential, of which jobs nobody started get half; nothing passes three times the daily cap), counted in `bridge/ledger.jsonl` in the Delphi home, where a failed call counts too. Jobs nobody started pause for 15 minutes after your last console call or host tool call, and after spent quota; a refused job stays due and raises a `budget` notice. A bridged call always waits for a Council or Panel seat or an agent on the same endpoint (`[routing] single_call_harness_parallel`, default 2, is how many run at once), and one that runs too long is stopped (`[routing] single_call_harness_timeout_secs`, default 180). Each call leaves a seat receipt and an `agent.usage` event with `cost_model = subscription`. There is no OS sandbox behind the call. Checked against `claude` 2.1.332; no real call has yet gone through it end to end (that is slice E), and the commands to start a job by hand and to pass a limit are slice F.
