# Xenia X10 conformance map

Each row maps one numbered test of `specs/011-xenia-trust-model.md` §10 (1-31) or `specs/012-xenia-record-schema.md` §10 (1-23) to the named tests that implement it, as `<path under crates/>::<test function>`. The right-hand column carries notes, and the honest limits.

**This table is checked by a test.** `crates/delphi-xenia/tests/conformance.rs` reads the numbered lists out of the two specs, reads this table, and fails when: a spec test number has no row; a row has no test; a named test does not exist as a `#[test]` function in the named file; or this table names a number the spec does not have. A new numbered test in either spec therefore turns the build red until a row and a test exist.

A mapped name proves the test exists and is run by `cargo test --workspace`. It does not prove the test is sufficient for the numbered requirement; the "Notes" column and the red-team checklist (`xenia-x10-redteam-checklist.md`) say where it is not.
