| 119 | B7 | the host as a search source (§2.1 items 1 to 7, §13.1) | built and merged (#744): in a host whose adapter names a search tool (the host tool table is `mcp_hosts::host_search_tools`, read from the adapters of spec 110: Claude Code only today), `request_research` queues a run with `sources: host` and answers with `host_search: "asked"`, the host's tool name and the queries the run planned, each cleaned and through the identifier guard (it waits up to 25 seconds for the plan; `research_status` lists them under `host_search` when the plan takes longer); `runner: "daemon"` asks for Delphi's own runner. The new host method and MCP tool `research_feed {research_id, query, results[]}` is taken only from the session that raised the run, only for a query the run asked, exactly as asked, once each, with at most 10 http(s) addresses, at most 12 queries, and only while the run waits (240 seconds, a constant; `HOST_METHODS` is 32, `HOST_SURFACE` 32, `MCP_SURFACE` 46, each with the new row). Only a result's address is kept: titles and snippets are dropped at the socket. The run reads a fed address that is on the trusted list through the daemon's fetcher; any other is never fetched (it is counted in the log as `lead` and listed in the result as `host_leads`), is not stored as a library lead, and never enters the set of addresses a search of the run returned. Under the private-read mark a feed is leads only (as `record_research` fetches nothing under it, 113 §2 item 5): an operator question, since §15 says a marked session researches as any other. Each fed search is a log line marked `run_by_host` with source `host:<tool>`. With engines configured, the queries the host did not hand back, and the later rounds for sub-questions still uncovered, go to the engines; with `providers = []` the run ends after the host's turn (`engines: none` of §2.1 item 6 is said as `sources: host` with no engine line in the log). Found while building: the existing socket tests of the daemon's runner use the tool name `claude-code`, so they now pass `runner: "daemon"`; the B9 local-run test moved to a host with no search tool (Codex). Not done: no real host has run the loop; the 240-second wait and the 25-second plan wait are guesses; a host row beyond Claude Code's (Copilot lists a fetch tool and no search tool; Antigravity and Gemini CLI have no adapter) |
