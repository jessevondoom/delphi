Built 2026-11-27 on the branch `build/145-a` (from `knowledge-v2`; pushed, no pull request; the lead integrates).

**The switch is off.** `delphi_core::provenance::TAINT_TABLE` is `TaintTable::Ratified`: the table of GOVERNANCE §4.3 as ratified, under which a span at `L1` or below loses its mutating and outbound tools and a dispatch it requests is a Red card. `provenance::gate` is that table, unchanged, for every tier and action. The new table is `TaintTable::WhatLeaves`. It is a constant on purpose: no configuration key, flag, environment variable or agent sets it. Each span carries the table it runs under (`Span::under`, inherited by `Span::child`); the engine puts every span under `Settings::taint_table`, whose only value outside tests is the constant (`boot::settings_from` never sets it). The tests of the new behaviour switch it on with `Settings { taint_table: TaintTable::WhatLeaves, .. }` or `Span::under`. **What turns it on:** after the operator ratifies slice G (the GOVERNANCE §4.3 diff and the `specs/001` §5.2 table), one reviewed pull request changes `TAINT_TABLE` to `TaintTable::WhatLeaves` (145-A1 item 5). Nothing else needs to change.

What is there, with the switch on:
- **`provenance::gate_in`** (`delphi-core`): for a span at `L1` or below, `WorktreeWrite` → Allow (the ordinary tier), `Outbound` → Red, `DispatchAgent` → Allow (the child starts at the parent's ceiling and table), `ConnectorWrite` Red, `Read` Allow. Untainted spans are the same under both tables. `gate_write` (promotion paths need `L4`) is unchanged.
- **The laundering rule becomes a mark** (`tools::gate_tainted_write`, in `write_file` and every artifact tool, file and sidecar). The write goes through; the file is stamped at the span's taint (`output_tier`, already `min(L3, ceiling)`), not the path's default. Still refused: `context/**` (the team's shared knowledge, kept at `L2` or above by `specs/007`; 145 does not open it), the never-writable lists, `.git`, and `gate_write`.
- **The notice**: `tools::taint_notice`, event `taint.write_noticed` with `path`, `tier`, `sources` and `text` = `wrote after untrusted text: <path> (taint <tier>, from <source ids>)`. One per file-tool write, one per file a tainted command changed, one per harness seat edit. The console shows it as a note (`ui/src/fold.ts`). Nothing waits on it. The span remembers what tainted it (`Span::sources`, at most 8): the logical path read, the held passage's path, the dispatched child's result, or the tool's name when a tool did not say.
- **145-A1 item 1, no network for tainted code.** The sandbox profile already has the network off for every command (`exec::ExecEnv::spec`, `Network::Off`; investigations likewise). New: a tainted span's command that would run unsandboxed (`[exec] sandbox = "off"`, or a harness seat's own `Bash`) is refused before any card (`engine::tainted_exec_refusal`), as the ratified table refuses every tainted command today.
- **145-A1 item 2, host-run files.** `tools::host_run` is the merge flow's one table, `worktree::is_host_exec` (GOVERNANCE §5.5, the Red flag at merge, with the ratified `host_exec_paths`), also matched case-folded. It is checked on the canonical worktree path; the guard refuses `..` and every symlink component before a byte is written, and a harness seat's edit is checked on the path as resolved.
- **145-A1 item 3, the full payload.** A tainted span's web request (harness `WebFetch`/`WebSearch`) is a Red card whatever the delegation, with `tools::tainted_outbound_payload`: destination, account, the whole request, attachments, taint and sources, inside the payload the answer is bound to (`payload_blake3`). A tainted connector write already carried connector, account, scopes and the full arguments. Both now carry `taint_outbound: true`, which `merge_class::console_only` reads: a relay reply cannot approve such a card (it can deny it).
- **145-A1 item 4, taint follows the work.** Found already true: resume (`recovery` takes the lowest `span.taint`), a model-call retry (the same span), a child's result (`exec_dispatch` observes the child's ceiling), a read of a stamped file (the mission index). New: the investigator's pushback retry starts at the first attempt's taint, not the parent's (a tightening, under either table).

Not verified, and limits:
- **Marks do not cross missions.** A stamp lives in its mission's log (001-A4); in a later mission a file a tainted span wrote at a path whose origin default is above `L0` (`missions/<m>/notes.md`, `specs/…`) reads back at that default. The ratified laundering refusal is what closed this; with the switch on it reopens for such paths. The mark is in the daemon's write log (the mission's `provenance.stamp` and the notice), which is what §2.2 item 1 asks, but nothing carries it into another mission. To decide before the switch is turned on.
- **Outbound kinds.** The engine's agents have no `gh` or agent-to-agent tool; their network writes are commands (sandbox, network off, or refused). The outbound kinds a span can request are a harness seat's web tools and connector writes, and both are tested. `verify_source` fetches from the network without `provenance::gate` (its own trusted-host card), as before; it is not changed here.
- A clean span is refused `..` and symlinks by the guard too, so AC-8's "the same write from a clean span is not refused" holds for the direct path only.
- `package.json` scripts, which the merge flow flags by content, are not in the path table and are not refused for a tainted span.
- The relay is kept from approving by the card's payload flag; it is not shown a partial card first.
