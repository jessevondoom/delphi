Built 2026-11-27 on the branch `build/144-s0-a` (based on `knowledge-v2`; no pull request).

**Citable text (§2.1 item 1).** `citable_text::citable_text(text, http_status)` is the fixed rule: a web capture's HTTP status (the capture record's `status`) was a success; the text is not empty; its **content share** (characters of sentences of ordinary text, at least `SENTENCE_WORDS_MIN` = 4 words, and table rows, against all its lines) is at least `CONTENT_SHARE_MIN` = 0.35, where links, menus (lines that are mostly link), headings, repeated lines, picture-only lines (counted neither way) and sentences of a boilerplate kind (soft 404, parked domain, CAPTCHA, paywall, cookie banner, each by a fixed phrase list) count as no content. A text that fails is named by the boilerplate kind that fills most of it, else `navigation`, else `only N% of the text is content`. `Library::citable(id)` judges a source's stored text, or with none held its kept and pinned excerpts; a source with only a summary has no text. Each exclusion is logged (`source_not_citable`, with the reason) in the library's log.

**Titles only (§2.1 item 2).** `Gathered::titles_only`: a source without citable text is no `RECORD`. `Library::gather` (search and topic pages) and `topic_gather::sort_hits` put it there; the brief lists it once under `SOURCES READ (titles only; not citable for what they say)`, by title. The seed's row 2 gives no summary span (a summary is not citable text); a source read without citable text, or with no excerpt, is only named (`Seed::named_sources`), and those names reach the brief's titles list. The page check rejects a marker naming such a source: `Finding::NoText`, "cited a source with no text".

**Research prose is not evidence (§2.1 item 3).** `Seed::citable_records` leaves out the research answer's spans: a written page's records and its check hold none of them (the seed page, which code writes, still cites them through `Seed::records`). The claim ids an answer's markers name (`[c-…]`, or `(c-…)` once cleaned; `topic_gather::claim_ids_in`) join the writer's claims (`Seed::answer_claims`, `topic_gather::follow_claims`). A hit on an `answer.md` in the index is no record either; its claims join. The topic brief says a draft block whose marker names no record is an outline (`topics::OUTLINE_NOTE`).

**Research topics leave out the repository (§2.1 item 4).** `topic_gather::is_repository_file`: `projects/<id>/files/…` or `@<project>/…`, outside the project's `research/`. `sort_hits` drops one for a topic whose origin is `research` (`research_origin`); that covers the seed's row 6, the writer's gathered evidence and so the validator's material (which is built from what the page cites and the topic's claims). Row 5 is untouched; an operator's topic keeps repository files.

Builder decisions where the spec is silent:
- The threshold (0.35), the sentence floor (4 words) and the phrase lists are fixed in code here; the trial (slice E) may tune them.
- A source whose stored text no longer matches its hash is not judged by `citable_text`: the check's own `SourceAltered` finding stands for it.
- A source's kept excerpts are citable when the source is; a pointer with excerpts is judged on its excerpts.

Not verified: the rule on real captures (the accept and reject fixtures are written by hand); the repository rule against a live index with a registered project (the index lists a project's files only to that project's own sessions today, so the rule is a guard).
