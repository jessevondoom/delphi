Built on the operator's go of 2026-11-23 ("build all the follow ups you just listed in as few PRs as possible"), in the quiet window it named (§14.14).

**E4a, the converter.** `delphi forge tracker migrate [--spec <spec> | --section <heading>] [--dry-run] [--repo <dir>]` (`crates/delphi/src/tracker_migrate.rs`). It reads the rows `tracker::rows` reads, keeps only those in a slice table (a header starting `| Slice |` or `| Spec | Slice |`; a roll-back table or a table of specs stays as it is), maps the state cell by §14.14's table (a cell that does not map clearly gets the closest state and says so in the file), takes the date from the cell, else the day of the last commit that changed the row (`git blame`, read-only), else the run's day, and `pr` when the state cell names exactly one pull request. The row itself, with its table header and heading, is the file's prose. A row under a heading naming several specs becomes one file per spec; two rows of one slice become one file (the first gives the state, as the readers took it). It never overwrites a file, and a row leaves the table only when every file it maps to was written; an emptied table becomes one pointer line to `delphi forge tracker --spec <n>`. Tests: `tracker_migrate::tests` (mapping, dates, pull requests, ids, a whole plan, filters, a dry run and a run that writes once).

**E4b, the run** (its own commit, generated by the tool; rerun it on that commit's parent with `cargo run -q -p delphi -- forge tracker migrate`).
