| 116 | G9 | the investigator's shell in a throwaway worktree: the manifest, the worktree's life, the unchanged-project test, the refusals | built and merged (#742), for the red-team before merge: the investigator's manifest gains `shell-worktree-scoped` and `git-worktree`. Its `run_command` and `shell` run in a copy of the project made at the span's first command and deleted when the span ends (a guard that deletes on any exit, and a sweep of leftovers). Found while building, and different from the spec's words: the copy is a repository of its own (`git init`, then the daemon fetches the project's branches, tags and head into it and checks out detached), not a linked worktree, because a linked worktree keeps its index, refs and new objects inside the project's `.git`, and the sandbox refuses every write to a `.git` path; the copy's git directory is beside its files under another name. It has no remote. Commands ALWAYS run in the OS sandbox with no network, also when `[exec] sandbox` is off (a builder's then run unsandboxed); with no sandbox on the machine the tools are not offered. Cards, deny rules, the Hard class and the taint gate are the builder's code path; push, fetch, pull, clone, remote and submodule are also refused by name. `builds` (scope and an `@worktree/` write glob) now decides everything that used to read the scope alone: a task's worktree, a harness CLI's own tools, the route's approval bridge, and an operator authorization (spec 092), none of which the investigator gets. Tests hold the whole project directory byte-identical (`.git` included) after a bisect (AC-10) and after a push, a network request and writes outside (AC-11). Limits: the copy costs a full fetch of the project's history; on macOS `/usr/bin/git` is a shim that does not run in the sandbox, so `[exec] toolchain` and `PATH` must name a real git; a span already untrusted (it read research or web text) is refused the shell as a builder would be; a harness seat without the tool bridge has no shell |
