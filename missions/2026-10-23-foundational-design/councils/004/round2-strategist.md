### 2. Explicit Resolutions

- **(a) Post-D-03 `REVIEW.md` / `GOVERNANCE.md` loading:** Critics and `review-md-audit` load `local/ratified/REVIEW.md` and `local/ratified/GOVERNANCE.md` (with `operator/ratified/` and `base/` precedence per [006-installer-and-updater.md](../../../../specs/006-installer-and-updater.md#L113) §3.1), which `delphi-core` pins in memory at task start. When auditing a repository that itself tracks `REVIEW.md` or `GOVERNANCE.md` (e.g., Delphi's own source repo), `delphi-core` also enforces `git show <base-ref>:REVIEW.md` (`origin/main`, falling back to local `main`) so a PR branch cannot weaken its own rubric ([`[REV-SEC-04]`](../../../../REVIEW.md#L22)).
- **(b) Spec self-approval:** Agree with Red-Team, refined for zone separation: only the operator may ratify a spec (`status: approved`). `delphi-core` blocks any agent write setting `status: approved` and verifies at `Spec-Gate` ([003-collaboration-and-council.md](../../../../specs/003-collaboration-and-council.md#L73)) and Merge Gate 3 (`#L65`) that the linked `specs/NNN-*.md` has an $L_5$ (`user_ratified`) entry for its exact `(zone, path, blake3)` in the authoritative provenance index ([001-governance-and-manifests.md](../../../../specs/001-governance-and-manifests.md#L217) §5.1) and `local/ratified.lock`. Any post-approval edit invalidates the hash and requires re-ratification. For spec-less `L2` bug fixes/doc updates, replace `"non-trivial tasks"` with a hard rule: `L2` without a ratified spec is allowed only when touching $\le 3$ files and $\le 150$ changed lines outside `host_exec_paths`, `GOVERNANCE.md`, `REVIEW.md`, `agents/**`, and `skills/**`, and still requires operator approval at Merge Gate 5.
- **(c) Step 2 Go/No-Go scope:** Step 2 delivers `L1` and read-only `L2` only (discovery, spec authoring/review, threat modeling, and codebase Q&A across `orchestrator`, `architect`, `red-team`, and `strategist`, writing only to `missions/**` and `specs/**`). Worktree-mutating `L2`/`L3` (`Builder`, `.delphi/worktrees/<task-id>`, OS sandbox, Merge Gates 1–5) ship in Step 3 per [roadmap.md](../../../../missions/2026-10-23-foundational-design/roadmap.md#L54-L55).
- **(d) Redaction vs. signed reasoning:** Never mutate a signed `thinking` block in place while keeping its `signature`. If the deterministic redactor ([005-console-and-narrator-tui.md](../../../../specs/005-console-and-narrator-tui.md#L115)) matches a secret in `thinking.thought`—or when `delphi gc` compacts closed missions after 30 days—`delphi-core` masks/compacts the text, **drops `provider_meta.signature`**, sets `signature_dropped_reason: "redacted" | "gc_compacted"`, and replays the block only as an unsigned assistant `<prior_reasoning_note>` with closing-tag escaping. Provider-opaque `redacted_thinking { data }` blocks contain no plaintext and are echoed byte-for-byte on matching `(provider, endpoint_id, model_id)`. `delphi gc` never compacts open missions/tasks.
